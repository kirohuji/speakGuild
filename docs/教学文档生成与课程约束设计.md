# 教学文档生成与课程约束设计

> 状态：设计提案  
> 适用范围：`TrainingTopic.teachingMarkdown` 的单篇生成、场景批量生成，以及后台的人工编辑与审核。

## 1. 要解决的问题

教学文档不是把单词、语法规则和例句重新排一遍，也不是一段轻松的“老师口播”。它的职责是帮助学习者在一个具体场景里形成英语表达的路径：**我此刻想完成什么 → 我可以怎样开口 → 说完后下一步怎样接**。

现有生成方式有三个根本限制：

| 现状 | 后果 |
| --- | --- |
| 先绑定材料，再直接让模型生成长 Markdown | 模型只能“解释已有清单”，无法先判断本课真正需要哪些可输出的语言支架。 |
| 仅把后序包材料以文本放进 prompt | 模型可能不用被列出的原文，却用同一个后序句式、变形词或新词；生成后没有程序化校验。 |
| “自由发挥、像老师 briefing”缺少版式和教学颗粒度约束 | 容易出现聊天式开头、机械公式、重复词表和过度语法术语。 |

因此应把“选教材”和“写教学文档”拆开：先得到可审核的**话题教学设计**，再由这份设计生成面向学习者的 Markdown。文档只能使用教学设计已批准的语言材料；模型不能自行发明教学目标或新增英文表达。

## 2. 教学原则

1. **交际优先。** 每节课以一个可观察的交流任务开始和结束，例如“在教室门口自然开始一段 2 轮交流”，不以“掌握某条语法规则”为目标。
2. **母语式路径，不回避准确性。** 先让学习者听见、模仿和替换完整表达，再在必要处用很短的中文指出差异。语法是帮助表达更准确的“使用提示”，不是本课的主体，也不使用“公式”“主谓宾”“特殊疑问句”等初级学习者无法直接转化为输出的术语。
3. **一句能立刻说，多个句子能灵活说。** Chunk 负责即时开口；句型骨架负责替换与迁移；词汇负责填入有意义的信息。三者必须在同一段小对话或替换练习中相连，不能各自成表。
4. **少而深。** 一课只承担一个核心交际动作和有限的新材料。新材料必须进入示范、控制练习和自由输出；不能进入这些环节的材料不应标为本课核心。
5. **累加而不抢跑。** 已学内容可作为复习支撑；当前课的新内容必须首次明确引入；后序包和后序话题的新内容不可提前教授、不可作为例句关键答案、不可用“顺带一提”方式泄露。

## 3. 产物与职责边界

生成链路应有两种产物。

| 产物 | 面向对象 | 作用 | 是否可直接展示给学习者 |
| --- | --- | --- | --- |
| `TopicTeachingDesign`（结构化教学设计） | 编辑、审核与生成服务 | 定义目标、可用材料、语言支架、练习路径和边界 | 否 |
| `teachingMarkdown`（教学文档） | 学习者 | 将批准的设计组织为可读、可练的课前指导 | 是 |

`TopicTeachingDesign` 是权威来源；Markdown 是其渲染产物。人工可以编辑 Markdown，但一旦编辑引入新的英文内容，必须重新通过范围检查。长期应把设计保存为 `TrainingTopic.teachingDesign`（JSON）或独立表，并记录 `designVersion`、生成模型、审核结果与时间。

## 4. 生成前：先形成教学设计

### 4.1 输入上下文

生成服务应一次性读取以下内容，而不是只读取当前话题的三个关联表：

| 上下文 | 用途 |
| --- | --- |
| 当前学习包、组顺序、CEFR / L 等级、场景和话题任务 | 决定交流复杂度、语域和输出长度。 |
| 同包前序话题的已认领材料及教学设计 | 判断哪些可复习、避免重复把同一目标再教一遍。 |
| 同包后序话题的 `learn` 材料 | 形成绝对禁区，防止提前引入。 |
| 前序学习包的 `learn` / `review` 材料 | 形成可调用的复习池，并标明首次引入位置。 |
| 后序学习包的 `learn` 材料 | 形成绝对禁区。 |
| 当前候选库（词汇、Chunk、Pattern 的释义、难度、例句、搭配、使用记录） | 只能从候选库提出新材料；优先复用已存在资产。 |
| 当前话题的故事 / 对话 / 图片任务（如有） | 确保示例与练习发生在真实场景，而不是泛用例句。 |

其中“后序”不应只依赖词面禁词表。必须同时传入材料 ID、类型、难度、首次学习位置和语义说明；模型的提议回收后还要由程序按 ID 复查。

### 4.2 `TopicTeachingDesign` 最小结构

第一阶段要求模型只返回 JSON，禁止返回 Markdown。所有 `id` 必须来自传入候选库；`create` 只允许作为“待审核建议”，不能自动发布。

```ts
type TopicTeachingDesign = {
  objective: {
    situation: string;          // 何时、面对谁
    communicativeAction: string; // 要完成的动作，而非语法名
    successCriteria: string[];  // 2–3 条可观察的输出标准
  };
  scope: {
    level: string;
    newMaterialIds: MaterialRef[];
    reviewMaterialIds: MaterialRef[];
    forbiddenMaterialIds: MaterialRef[];
    excludedConcepts: string[]; // 本课不展开的相关语言点
  };
  languageSupports: {
    anchorChunkIds: string[];   // 1–2 个可直接开口的核心表达
    patternIds: string[];       // 0–2 个能替换信息的骨架
    vocabularyIds: string[];    // 仅填入骨架所需的词
    links: Array<{
      chunkId: string;
      patternId?: string;
      vocabularyIds: string[];
      function: string;
    }>;
  };
  learningPath: {
    notice: string;             // 学习者先要听出/看出的差异
    modelDialogue: DialogueTurn[];
    guidedVariations: Variation[];
    outputTask: string;
    selfCheck: string[];
  };
  confusionChecks: Array<{
    contrast: string[];
    decisionCue: string;        // 用什么情境作判断，不写抽象规则
    minimalPair: DialogueTurn[];
  }>;
};
```

材料配置建议以“功能覆盖”而非固定数量为准。Foundation 的单个话题通常为 1–2 个锚点 Chunk、0–1 个新骨架、3–6 个核心词；更高阶段可增加信息密度，但每项仍须能进入输出任务。若当前绑定材料不足，系统应返回“缺少的交际功能 / 推荐候选 / 原因”，供编辑确认后再生成，不能让文档偷偷补上新知识。

### 4.3 语言支架的关联规则

每一项 `new_core` 必须能沿下列链路追踪到最终任务：

```text
交际意图
  → 锚点 Chunk（先能整句开口）
  → 句型骨架（替换一处信息）
  → 关联词汇（填入真实信息）
  → 两轮以上微对话
  → 新情境自主表达
```

例如“按时间问候并做初次介绍”中，`Good morning.` 是整句的开口选择，`I'm ___.` 让学习者填入自己的名字，`morning / afternoon / evening` 是帮助选择情境的词。它们不应被分成三段各自讲解，更不能写成 `Good + 时间段` 这样的抽象公式。

## 5. 生成后：必须经过两道校验

### 5.1 结构与教学质量校验

Markdown 生成后先解析为 AST，再检查：

- 存在明确的场景目标、至少一个真实微对话、至少一次替换或迁移任务、可执行的自检；
- 不含词表式标题或条目，例如“核心词汇”“句型列表”“实用表达”；词汇、Chunk、骨架只能出现在关联表、对话或练习中；
- 不含“公式”“结构特别简单”“只要套入”“主谓宾”“语法规则如下”等模板化话术；
- 不把语法术语作为一级教学目标；必要提示使用“说这句话时，英语需要把 … 说出来”一类可感知的说明；
- 表格仅用于帮助决策或建立关联，不做孤立的词—释义清单；表格列数不超过 4，移动端应可读；
- 文本长度按等级控制。Foundation 建议 350–650 个中文字符，Course 500–900，Advanced 按任务需要放宽；不要为了达到字数硬加寒暄。

这些规则大多可通过 Markdown AST、标题白名单/黑名单和正则检查。未通过时，将失败项和具体段落回传给“修订 Markdown”模型；最多修订两次，仍失败则进入人工审核，而不是静默发布。

### 5.2 范围、难度与顺序校验

英文内容应从 Markdown 的行内代码、强调文本、表格、对话和普通英文句中抽取，再做四类审查：

| 检查 | 判定 | 处理 |
| --- | --- | --- |
| 材料白名单 | 核心教学表达、替换词和练习答案必须映射到当前 `new` 或 `review` 的材料 ID | 无法映射时拒绝发布；可作为场景名/人名的少量白名单词除外。 |
| 后序禁区 | 命中同包后序或后序学习包的 `learn` 材料、其明确变体或对应目标句式 | 拒绝发布。 |
| 前序复习 | 使用已学材料但未标记 `review`，或把它讲成新知识 | 要求修订设计或降为复习提示。 |
| 难度预算 | 新词、句长、从句/时态等语言特征超过当前等级预算 | 降级改写或进入人工审核。 |

词面匹配不足以覆盖变形和同义替换。第一版应做到“材料 ID + 规范化词形 + 规则特征”三层校验：例如从 Pattern 的槽位和 Chunk 的文本派生可允许的变体；对未识别的英文片段一律报出；模型可对“是否构成未授权的新教学点”给出辅助判定，但它不能越过确定性拒绝规则。

现有 `MaterialConstraintService` 可继续作为材料认领的事实来源，但需要补充两个能力：按**当前话题序号**获取前序/后序话题的材料，以及输出带来源、角色、首次引入位置的 `CurriculumScope`。生成器和后台人工保存均使用同一套校验器，避免 AI 生成和手工编辑出现两套标准。

## 6. 学习者 Markdown 的固定骨架

版式应稳定，文内讲法可以随话题变化。稳定的阅读顺序会降低认知负担，也让审核变得可靠。

```md
# 本课：{可完成的交流动作}

{1–2 句具体场景：谁、何时、要做什么。避免鼓励性口播和泛泛开场。}

## 先听出这一步

{用一个短对比让学习者判断场景；必要时给一个 2–3 列决策表。}

## 这样把话接起来

{一段 2–4 轮对话。Chunk、骨架和词汇在同一对话中出现。}

| 你要完成的动作 | 可以先说 | 换成你自己的信息 |
| --- | --- | --- |
| {交际功能} | `{Chunk}` | `{Pattern + vocab}` |

{用 1–2 段中文说明“什么时候这样说、听起来是什么感觉、怎样换信息”。}

## 容易选错的地方

{只做与当前输出任务直接相关的最小辨析；用“见面/告别、熟人/正式”等情境选择，不做术语讲解。}

## 轮到你开口

1. {有支架的替换任务}
2. {拿掉部分支架后的两轮对话任务}
3. {迁移到相邻但不同的场景}

## 说完自己检查

- {是否完成交际动作}
- {是否用到了本课锚点表达}
- {是否根据场景作出正确选择}
```

表格的作用是表现“意图—表达—可替换信息”的关系，不是重复资产列表。整个文档应只出现一张关联表；其余内容使用短段落和微对话，让阅读始终服务于开口。

## 7. Prompt 设计

### 7.1 第一阶段：教学设计 Prompt

系统提示的关键约束如下：

```text
你是英语课程教学设计师。先设计学习者在真实场景中完成交流的路径，
不是写语法课，也不是整理词表。只返回符合给定 JSON Schema 的对象。

只能从 ALLOWED_NEW 和 ALLOWED_REVIEW 中选择可教学的材料 ID；绝不能创建或
使用 FORBIDDEN 中的材料、概念或其变体。不要把后续知识作为例句、旁注或扩展。

新材料必须同时出现在：示范对话、至少一次有支架的变化练习、最终输出任务。
Chunk 用于立刻开口；Pattern 用于可替换的信息位置；Vocabulary 只能服务于前两者。
如果给定材料无法支撑目标，返回 materialGaps，而不是自行补词或补句型。
```

用户提示按固定分区传入 `CURRICULUM_SCOPE`、`TOPIC_TASK`、`CANDIDATE_LIBRARY`、`EXISTING_APPROVED_MATERIALS` 和 `OUTPUT_SCHEMA`。不要再向模型传入一串没有来源和角色的禁用文字。

### 7.2 第二阶段：Markdown Prompt

```text
根据已审核的 TEACHING_DESIGN 写一篇面向学习者的 Markdown。

它是一次严谨、可练习的课前指导：从具体情境进入，展示完整表达如何接成对话，
再让学习者替换并迁移。不要把英语拆成公式，不要教授超出设计范围的语法，
不要使用聊天式鼓励、夸张承诺、词表标题或“背住即可”。

所有英文教学表达、对话和练习答案只能来自 ALLOWED_LANGUAGE；人名、地点等
SCENE_ALLOWLIST 除外。每个英文表达必须在设计中有对应材料或对话位置。
严格使用给定 Markdown 骨架；一张关联表、一个最小辨析、一个由易到难的开口任务。
```

温度建议：设计阶段 `0.2–0.35`，Markdown 阶段 `0.35–0.45`；重点由结构化输入和校验保障，不依赖温度“碰运气”。

## 8. 示例：Topic 01 的期望呈现

以下仅展示文风和排版，实际英文范围必须由当前 Topic 已批准的材料决定。

```md
# 本课：见面时自然开口

早上走进教室、下午参加活动，或者傍晚在小区碰到邻居，第一句话要让对方马上听出：你是在自然地开始交流。

## 先听出这一步

见面时，英语会把时间和关系带进问候里。早上见到老师，说 `Good morning.`；下午再见面时，换成 `Good afternoon.`。晚上刚碰面用 `Good evening.`；准备离开或睡前才说 `Good night.`。

## 这样把话接起来

> Emma: Good morning.
>
> Lin: Good morning. I'm Lin.
>
> Emma: Hello, Lin.

| 你要做什么 | 先说什么 | 接着怎样说自己 |
| --- | --- | --- |
| 早上开始交流 | `Good morning.` | `I'm Lin.` |
| 和同学轻松打招呼 | `Hi.` | `I'm Lin.` |

`Good morning.` 是完整的开场，不需要把它拆开再补一句“good day”。说完问候，直接用 `I'm` 加上自己的名字，对话就有了下一步。

## 容易选错的地方

刚见面：`Good evening.`。准备分别：`Good night.`。两句话都和晚上有关，但一个用来开始交流，一个用来结束交流。

## 轮到你开口

1. 现在是下午。先对老师打招呼，再说出你的名字。
2. 你在教室门口遇到新同学。用 `Hi.` 或 `Hello.` 开始，再介绍自己。
3. 想象傍晚遇到邻居：说一句合适的问候；离开时再换一句合适的话。

## 说完自己检查

- 我有没有按“见面”还是“告别”选对问候？
- 我能不能在问候后自然接上 `I'm ...`？
```

这段示例避免了“`Good + 时间段`”的公式化表达，也不将 `morning / afternoon / evening` 单列为词表；学习者看到的是一条在真实情境中可以直接执行的表达路径。

## 9. 落地顺序与验收

1. 新建 `CurriculumScopeService`：汇总当前、前序、后序包与话题的材料及首次引入位置；补齐包内话题顺序查询。
2. 定义 `TopicTeachingDesign` DTO / JSON Schema 和持久化字段；后台增加“设计—材料映射—风险”预览，不直接把模型 JSON 当作 Markdown。
3. 将 `TopicTeachingGenerateService` 改为两阶段生成，并删除/复用 `content-admin.controller.ts` 内重复的故事教学文档 prompt，避免两条链路口径漂移。
4. 实现 Markdown AST、英文片段、材料映射、难度预算四类校验器；人工保存也调用它。
5. 在后台显示校验结果：新学、复习、禁用命中、未映射英文、重复教学、难度风险；高风险项必须人工确认。
6. 用 Foundation 1 的 12 个 Topic 做金标回归集，人工评分“场景明确、可直接开口、材料关联、无超纲、无公式化语法讲解”五项；任一项不通过不得批量发布。

验收不以“生成了 500–900 字”为标准，而以每篇文档是否能证明以下事实为准：学习者知道在什么情境开口、能用当前课获批材料完成一次输出、能把一句话换成自己的信息，并且没有提前学习任何后续内容。

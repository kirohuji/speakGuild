# 知识点练习判题设计

状态：云端文本判题规则已接入 `EnglishPracticeAiService.judgeWarmupTurn`，包含题型/方向分流、句型语法例外和四档评分；代码更新不代表已部署。长句拆解的录音转写接入、对话重新接入知识点列表仍属于后续工作。现有 MiniLM 离线评分已通过有限语言检查与相似度组合接入，验证和边界见 `minilm-q8-offline-improvement.md`。

## 范围与约束

复用题库现有字段，不新增数据库列、逐题评分说明或规则引擎。一次正常判题只调用一次模型。公共规则、题型规则、方向规则组合成 prompt，避免维护多份重复内容。云端明确关闭供应商支持的 thinking；返回现有 `passed、score、feedback、correction`。

题干决定意思，显式目标决定练什么，参考答案提供一种正确实现。参考答案不是唯一答案；没有显式目标时，不从参考答案擅自增加强制要求。题型、方向、目标与当前小题必须完整传给模型，不能把整个题组混作一道题。

## 按题型处理

| 题型 | 复用的题库数据 | 中译英 | 英译中 |
| --- | --- | --- | --- |
| 单词替换 | `chunk`、`kind=word`、`chunkMeaning`、小题 | 核验指定词的语境义和合理词形，不接受绕开目标的同义词 | 理解目标词在当前句子中的意思，不要求出现英文 |
| 词块替换 | `chunk`、`chunkMeaning`、小题 | 核验核心搭配及论元关系，允许题意要求的时态、人称、限定词变化 | 理解词块语境义和整句关系，不逐词对应 |
| 词汇练习 | `targetWords`、`promptZh`、`suggestedAnswer`、方向 | 核验明确要求的目标词，不能只列词或附在句尾 | 理解整句和目标词语境义 |
| 一词多句 | `vocabWord`、当前 `patterns[].chunk`、当前小题 | 核心词和当前搭配都要满足；二者重合时一次使用即可 | 理解该搭配中的词义和整句意思 |
| 句型操练 | `pattern`、`patternMeaning`、当前小题 | 核验结构关系、固定部分和槽位类型，不能用别的结构绕开 | 理解结构表达的条件、比较、时间、使役等关系 |
| 长句拆解 | 当前及前一级 `levels`、`highlight`、录音转写 | 按当前跟读形式，核验本级内容和新增结构；不要求后一级内容 | 当前没有该方向，不增加翻译模式 |
| 对话（当前列表未接入） | 已有意图、必要信息、目标表达 | 交际模式按意图与必要信息；明确的目标输出模式另核验指定表达 | 不套用翻译题规则 |

翻译方向要先规范化：现有英译中既可能使用 `en + answer`，也可能使用旧格式 `answer=英文、zh=中文`；沿用已有读取逻辑，不能把源句与参考译文交换。

## 句型格式

数据库实际包含 `[someone]`、`[something]`、`[V-ing]`、`[past participle]`、`[noun/doing]` 等占位符，也有中文 `+` 公式、完整表达和省略句。不用正则生成完整语法判定器，由模型结合模板、含义和当前参考答案理解结构。

- 方括号是带类型的槽位；`[noun / V-ing]` 是槽位内的选择。
- `Nice / Good to see [someone]` 的斜杠是模板分支，不能对所有斜杠统一切分。
- `Pretty [adjective]` 允许省略句，不能要求补主谓结构。
- `It takes ...` 允许题意要求的 `It took ...` 及 `How long does it take ...`；不是所有句型都允许任意时态、语序变化。
- `take [someone] to [place]` 遇到 `home` 不加 `to`；语言规则优先于模板字面。
- 词块写成完整句时允许嵌入：`I'll get back to you` 可用于 `I'll check and get back to you tomorrow`。

模板存在正常语法例外时，结合 `patternMeaning` 与合法参考答案解释结构，不能反而要求用户写出错误的字面形式；这条优先于固定词匹配。

已有 `slots、description、examples` 可在关联明确时辅助理解，不要求每题都有，不全量塞入 prompt，不按相似文本强行匹配其他句型。讲解和题目数据可能有错，不能把一条错误讲解当作绝对语法规则。

## 判题与反馈

模型检查两件事：主要意思是否一致、训练目标是否正确使用。核验否定、主客体、关键数量/时间、条件和情态；目标必须真正参与表达。目标外的小错宽容处理，目标内的关键结构错误不能放行。大小写、标点、无害拼写差异不应导致不通过。

| score | passed | 标准 |
| --- | --- | --- |
| strong | true | 意思基本一致、目标满足、表达自然 |
| ok | true | 意思与目标满足，训练重点之外有轻微语言问题 |
| weak | false | 部分意思正确，或意思正确但目标遗漏/用错 |
| miss | false | 核心意思错误/相反、答非所问、作答语言错误或空答案 |

可以只让模型输出 `score、feedback、correction`，服务端从 score 推导 passed，保持现有对外返回不变。前端保留 weak 与具体反馈，不能统一改成 miss 或“再试一次”。使用提示造成的掌握度降级属于现有学习记录逻辑，不应反过来改变答案是否正确。

反馈短而具体：指出缺失的目标或改变的意思；通过时 correction 为 null。正确同义表达不强制改成参考原句。模型对有效回答给出明确评分；只有格式无效或结果自相矛盾时，最多重试一次，不默认双模型、双次调用。网络/供应商错误属于技术故障，不能记成答题对错。

## 长句拆解与离线边界

长句拆解当前只是录音和完成流程，没有 AI 判题，走完直接记 strong。以后接入录音转写后才能逐级判定，不能把流程完成当作掌握。文本判题不评价发音质量。录音/识别失败应提示重录，不记为英语能力错误。

离线沿用现有 MiniLM，使用通用目标结构/关键含义检查和相似度组合判分，不直接向嵌入模型发送 prompt。有效题目在本地给出评分，断网不转云端。Q8 结果与尚未完成的真机验证见 `minilm-q8-offline-improvement.md`；不能把有限规则等同于完整语法理解。

## 云端调用与验收

优先复用现有 `LlmChatClient.completeJson` 与供应商适配器；供应商只支持 `json_object` 时，用 JSON 模式加应用层格式校验，不强行发送不支持的 `json_schema`。显式 `thinking: disabled`，正常题目一次请求，输出控制在约 600 tokens。

验收按题型与方向分别覆盖参考原句、合法改写、词形变化、目标缺失、重点语法错误、否定、主客体、数量/时间和非重点小错。真实模型测试与模拟流程测试分开统计；先处理误放行、误拒绝及技术失败，不用一个总准确率掩盖问题。不因为少量测试通过就保证零误判。

实际学习包、测试 prompt、样例及结果见同目录 `warmup-cloud-evaluation.md`。供应商协议兼容与题型/方向 prompt 已接入云端业务方法，前端保留真实反馈与评分；长句拆解的录音转写另行接入，不将走完流程算作已验证答对。

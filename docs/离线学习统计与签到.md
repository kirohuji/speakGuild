# 离线学习统计与签到

> **核对日期**：2026-11-18  
> **范围**：学习统计投影、计时、日历详情、离线签到与积分补签。  
> **相关**：[离线同步与账号](./离线同步与账号.md)

---

## 1. 账号与状态

沿用现有单用户 SQLite 数据区、退出清空和切号清理。统计表加入同一用户清理列表，统计 Zustand 在同一边界 reset。清理前暂停新同步、等待当前同步和本地写入完成；旧计时器和旧统计读取结果通过账号代次失效。公共学习包与资源不受影响。

Zustand 只保存活动计时来源、未提交增量与最多六个统计日期范围的缓存，不再 persist 全部历史时长。SQLite 是持久化事实和统计结果的来源。

## 2. 前后端实现

- 前端：`sqlite/statistics-schema.ts` 维护 SQLite 触发器；`statistics-projection.ts` 生成远程数据的增量投影；repository 按索引日期范围读取。
- 后端：迁移 `20261114000100_learning_statistics_projections` 中的 PostgreSQL 触发器在学习事实事务内维护服务端投影，`LearningStatisticsService` 查询投影。
- 前后端没有互相导入聚合源码。

不包含旧版格式迁移或兼容回填。新结构上线前需要应用服务端迁移。

## 3. 表和口径

| 表 | 口径 |
|----|------|
| `learning_stat_day_questions` | 日期 + 题目 ID 唯一；当天重练不增加题数 |
| `learning_stat_questions` | 题目 ID 唯一；跨日复习不增加累计不同题目数 |
| `learning_stat_sources` | 日期 + 来源唯一；同来源取累计秒数最大值 |
| `learning_stat_days` | 每日题数、有效秒数 |
| `learning_stat_totals` | 累计题目、学习日、日题数之和、有效秒数；SQLite 同时维护收藏和单词数 |

作答事件保留发生时的本地日历日期。对话轮次不混入去重题数，时长仍参与学习活动。连续天数从今天开始；今天未学习时从昨天开始。签到奖励和学习活跃度分开。

月查询只读取可见日期范围，年度最多 366 条每日汇总。没有单独月表／年表。

## 4. 保存与计时

正在学习且 App 可见时，每五秒提交当前变化来源。无操作超过六十秒后不累计。同设备只有当前计时器拥有计时权。计时使用单调时钟，日期归属使用日历时间，跨午夜拆分。切后台停止计时器，回来建立新起点，不补算后台时间。

作答事实和 outbox 通过原子批次写入，SQLite 触发器同事务更新去重关系和汇总。重试同一事实不重复计数。

## 5. 同步与通知

统一前台调度器每三十秒提供一次上传机会：账号有效、App 可见、网络可用、有待同步项。无队列时停止周期数据库检查，直到收到新的 outbox 写入通知。周期任务只上传队列，不拉全量内容清单；前台恢复、登录和手动同步仍走既有同步流程。

每轮最多获取一百条到期记录。普通失败保留且指数退避。上传只确认对应的不可变修订版本。练习 run 的拉取游标采用更新时间 + ID 稳定分页。

远程题目和来源按批次投影。统计组件只订阅可见日期范围；未完整同步历史时显示不完整状态。

## 6. 日历详情与积分补签

默认打开今天的日视图。月视图单击日期持续高亮，双击（移动端连续轻点两次）进入当天日视图。日视图展示签到状态、完成题数、练习分钟三张卡及小时 chart；补签入口在顶部签到状态卡内。

补签固定消耗 **200 积分**，只允许过去尚未签到的日期。今天使用正常签到，未来不可补签。补签不发积分、不伪造练习记录，只参与签到连续天数。确认请求不进入离线 outbox。

迁移：`20261114000200_makeup_check_in`。可运行 `python3 apps/backend/scripts/test-makeup-check-in.py` 做临时集群验证。

## 7. 小时统计

SQLite 与 PostgreSQL 各自维护 `learning_stat_hours` 和 `learning_stat_question_times`。小时读取按日期索引，最多 24 条。计时在整点和午夜拆分，来源后缀 `:h00`～`:h23`。题目按当天首次事件时间归入小时。

迁移：`20261114000300_hourly_learning_statistics`，SQLite schema 版本 17。小时投影首次初始化会从已有练习历史补齐可恢复明细。

## 8. 离线签到

正常签到统一先写本地。`check-in.repository.ts` 在同一本地事务中保存签到记录和 `check_in` outbox 操作，成功落盘后首页显示签到成功。在线时立即尝试 syncPending，离线时保留队列。签到记录使用账号和日期去重。

首页和日历从同一份记录投影签到状态。服务端签到确认后更新可用积分，离线签到不提前增加可消费积分。

服务端继续使用 `/points/check-in`，额外接受 `date`、`occurredAt`、`timeZone`、`clientMutationId` 和 `ownerId`（仅账号一致性断言）。无 body 的旧调用仍表示当天签到。离线签到日期不能是未来。

沿用用户行锁和 userId/date 唯一约束；同一天重复请求返回已有结果。付费补签仍需联网。

账号切换暂停写入并等待当前本地事务完成，再执行既有账号清理。清除本地用户数据仍会清除未上传签到。

部署顺序：先部署支持离线日期与幂等响应的后端，再更新客户端。

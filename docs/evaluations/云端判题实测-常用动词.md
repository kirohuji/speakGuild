# 常用动词300个：高频核心——云端判题实测

日期：2026-11-15。设计见 [知识点练习判题](../知识点练习判题.md)。本文为历史实测归档；本次只读取数据库、写设计/测试文档及运行独立评测，没有修改业务代码、题库、模型配置或用户答题记录。

## 结论

云端题型/方向规则已正式接入业务方法，最终真实服务复测 172/172 符合预期，见文末“正式接入判题方案”。下文保留设计阶段与调用兼容性修复的历史过程。

当前工作区的业务判题调用存在供应商协议兼容故障，不能说当前云端判题没有问题。改用项目已有 JSON 客户端，在独立脚本中评测拟定的分题型/方向 prompt：首轮 147/148 符合预期；针对发现的语法例外误拒绝澄清 prompt 后，第二轮 162/162 符合预期。第二轮包含重复稳定性测试，不是 162 道独立题目，也不是生产接口已修复。

## 数据和模型

- 数据库学习包标题：`常用动词300个:高频核心`，id：`cmu2gj0ca0009152od86mwdv9`。
- 12 个话题中，只有“核心动作与日常表达”配置了知识点练习，当前题目主要围绕 get、take；其他 11 个话题未配置此类题目。
- 108 道可提交翻译/输出小题：词块中译英 41、词块英译中 6、一词多句中译英 18、句型中译英 41、句型英译中 2。
- 另有两个长句拆解题组，共 7 级；当前没有 AI 判题入口，不纳入上述云端正确率。
- 使用数据库当前激活供应商 `deepseek`，模型 `deepseek-v4-flash`，未修改选择。数据库配置只在内存中使用，产物不含密钥。
- 预期结果由本次评测依据题干和显式目标标注，没有让被测模型自己生成标准标签；尚未经过独立教师复核。

## 当前调用故障

直接运行当前工作区 `EnglishPracticeAiService.judgeWarmupTurn` 的参考答案样例：

- 题干：我通常九点到公司。
- 目标：get to work。
- 回答：I usually get to work at nine.
- 业务结果：异常“暂时无法核验目标表达，请重试；本次不计成绩”。

进一步对相同 AI SDK 请求诊断，供应商返回 `invalid_request_error`，错误信息为 `This response_format type is unavailable now`。该调用使用的结构化输出格式不被当前端点接受，异常被业务兜底包装后，看不出真实原因。重复冒烟和独立诊断均复现，因此停止通过这一故障路径跑全量，避免无意义请求。

后续实现应复用已有 `LlmChatClient.completeJson`，使用供应商支持的 `json_object`，并在应用层校验结果。不需要新增厂商专用客户端。本次没有将该改动接入业务。

## 独立方案测试

测试脚本使用同一数据库题目与模型配置、项目已有 JSON 客户端、`temperature=0.1`、`maxTokens=600`、显式 `thinking=disabled`。正常样例一次请求，没有用反复调用直到答对的策略。只把题目输入给模型，不传预期标签。

组合方式为“公共规则 + 题型模块 + 方向模块”。实际测试的最终 prompt 原文保存在 [当时的 prompt 文件](./warmup-core-verbs-design-prompts.json)，仅为设计/评测材料，业务没有读取这个文件。

首轮包含 107 条题库参考答案、1 条缺少参考答案的正确回答和 40 条标注变体，共 148 次：147 次符合预期，1 次错误拒绝，没有错误放行或请求异常。

失败样例：

| 项目 | 内容 |
| --- | --- |
| 题干 | 开完会我送她回家。 |
| 句型 | take [someone] to [place] |
| 句型含义 | 带某人前往某地；home 前通常不加 to |
| 参考答案及回答 | I'll take her home after the meeting. |
| 首轮错误结果 | weak；声称缺少 to，建议改为 to her home |

同一输入在首轮另一次调用通过，说明模型会不稳定地把模板字面要求置于语法例外之上。

澄清公共 prompt：模板表示语法结构，题目说明与合法参考答案体现的正常语法例外也满足目标，不能额外发明“本题必须带 to”的限制。没有加逐题硬编码规则，也没有直接把参考答案相等当作通过。

第二轮完整重跑原 148 个样例，增加 4 个大小写/无害拼写/礼貌表达/重点语法样例，再增加 10 次 home 正确例外重复测试，共 162 次：

| 题型 / 方向 | 次数 | 符合预期 |
| --- | ---: | ---: |
| 词块替换 / 中译英 | 61 | 61 |
| 词块替换 / 英译中 | 12 | 12 |
| 一词多句 / 中译英 | 22 | 22 |
| 句型 / 中译英 | 62 | 62 |
| 句型 / 英译中 | 5 | 5 |
| 合计 | 162 | 162 |

其中应通过 138 次，应不通过 24 次；观察到错误放行 0、错误拒绝 0、请求异常 0。第二轮 home 正确例外在原样例、原变体及新增重复中共 12/12 通过，对应 `take her to home` 错误仍被拒绝。

样例覆盖正确改写、词形/缩写、槽位变化、未用目标、重点结构错误、否定、数量/时间、主客体颠倒、中文意译、无害小错与改判指令。不能把这些样例上的表现解释为所有潜在回答的准确率。

两轮分别观察到 148/148、162/162 次请求显式关闭 thinking，响应均未出现非空 reasoning_content。第二轮单次模型请求耗时中位数约 0.94 秒、最大约 1.62 秒；这是本次直连评测耗时，不含手机、语音识别、业务 HTTP、排队等耗时。供应商报告两轮合计约 250,555 tokens。

完整逐条输入、预期通过与否、实际评分/反馈、耗时均保存在 [结果 CSV](./warmup-core-verbs-results.csv)，包含首轮失败结果；未删除或覆盖失败记录。

## 题库问题和验证边界

“一词多句 / 说该采取行动”的第二小题“要是我们还不采取行动，问题会更严重。”没有小题级 `answer`；参考句被错放到上层 pattern。测试中没有静默修正题库或从上层补入答案，而是提交人工给定的正确回答 `The problem will get worse if we do not take action.`，两轮均通过。仍需单独修正内容，否则参考答案展示/提示可能有缺失。

本次是同一供应商当前配置下的模型调用评测，不是已部署手机端或 HTTP 接口端到端测试，也没有写入学习成绩。未覆盖音频识别、发音质量、离线模型、未接入的对话及长句拆解判题；本包没有单词替换和 vocab_drill 样例，这两个模块仍需用其他真实题目验收。

结论是拟定方案在本包现有输出题目及所列变体上可行，不是当前业务已修好或未来零误判。模型仍可能出现未覆盖的错误；后续发现的误判补为回归样例即可，不增加复杂的多模型投票、规则库或题库新字段。

## 调用兼容性修复验证

本节为后续实际修复记录，区别于上面的独立 prompt 设计评测。

对照 VN 对话发现，`judgeDialogueTurn` 使用 `generateText` 请求普通文本并自行解析 JSON，不会强制请求 JSON Schema。知识点判题使用 `generateObject`，在当前 DeepSeek 端点触发不支持的结构化输出格式。不是 DeepSeek 的全部调用都不可用。

现已在工作区将知识点判题按现有适配器能力分流：DeepSeek、百炼复用 `LlmChatClient.completeJson` 的 `json_object`，显式关闭 thinking，使用现有 Zod schema 在本地校验；其他供应商保留 SDK 结构化输出路径。没有修改 VN 对话、全局适配器、数据库或模型配置，也没有将独立候选 prompt 整体接入业务。

真实验证还发现，JSON 模式有时省略未使用的 `correction`，首次八例测试因此有一例校验失败。现仅将省略的 correction 规范为 null，关键判定字段仍严格校验；无效 JSON、缺少判定字段、错误类型、空响应和截断输出不能作为有效模型判定。

最终直接实例化修复后的应用服务，使用同一数据库配置的 `deepseek-v4-flash` 复测八例：

| 样例 | 应有结果 | 实际结果 |
| --- | --- | --- |
| get to work 参考答案 | 通过 | strong，通过 |
| 用 arrive at work 绕开指定 get to work | 不通过 | weak，不通过 |
| 加入否定改变意思 | 不通过 | miss，不通过 |
| get to work 英译中自然改写 | 通过 | strong，通过 |
| get used to work from home 重点结构错误 | 不通过 | weak，不通过 |
| get ready 一词多句参考答案 | 通过 | strong，通过 |
| It took her two days ... 句型参考答案 | 通过 | strong，通过 |
| take her home 语法例外参考答案 | 通过 | strong，通过 |

八例均返回实际模型评估 raw，未触发规则兜底；8/8 请求显式关闭 thinking，没有非空 reasoning_content。另外直接调用原 VN 判题方法一例：NPC 问到公司时间，回答 `I got to work at nine today.`，正常通过，思考模式关闭。

[真实服务验证结果](./warmup-transport-verification.json)保留实际输入和输出，不含密钥。自动测试共 30 个通过，覆盖原 SDK 路径、DeepSeek/百炼原生请求体、响应校验、截断/故障、token 记录及评分结果。前后端类型检查通过。

以上证明本次协议修复在工作区真实服务方法中通过验证，不代表已部署到线上或手机，也不替代全部题型的语义准确率评测。八例通过不能推断模型未来不会出现语义误判。

## 正式接入判题方案

业务代码现已正式使用分题型、分翻译方向的 prompt，不再仅在独立测试脚本中使用。`prompts/warmup-judge.prompt.ts` 定义公共规则、题型规则与方向规则，`judgeWarmupTurn` 通过 `buildWarmupJudgeSystem(dto)` 组合并实际发送给模型。没有从 docs 动态加载 prompt，也没有新增数据库字段。

句型模板按结构解释，结合题干、含义和合法参考答案处理语法例外；`take her home` 满足 `take [someone] to [place]`，不要求添加 to。这个例子作为语言规则说明进入 prompt，没有代码白名单或逐题自动放行。

模型只输出 score、feedback、correction，服务端由 score 推导 passed；有效回答不再返回 uncertain/confidence 状态。技术故障和不合法输出仍不伪造成绩。纠正内容在通过时清空，前端保留 weak 和具体反馈。

正式服务首轮对原 162 个样例实测：161/162 符合预期；home 例外全部通过，发现另一处错误放行：回答 `I will check it and reply to you tomorrow.` 没有使用要求的 `get back to you`，模型在反馈承认目标缺失但给了 ok。这个失败保留为 CSV 中 service-1 的记录，没有删去。

随后在公共规则末尾明确：目标缺失或使用错误必须 weak/miss，绝不能 ok；ok 只用于训练重点之外的无害问题。要求通过前确认实际实现各目标的表达，区分同一结构的语法例外与绕开目标的同义词替换。最终业务 prompt 与 [当前 prompt 留档](./warmup-core-verbs-prompts.json)一致，自动测试会验证题型/方向组合与留档一致，避免独立测试版本和业务版本再次脱节。

再次通过实际业务服务方法重跑原 162 个样例，并增加 10 次缺少 get back to you 的重复测试，共 172 次：172/172 符合预期，错误放行 0、错误拒绝 0、技术异常 0；全部有真实模型 raw，没有依靠参考答案匹配兜底。138 次应通过、34 次应拒绝。home 正确例外 12/12 通过；reply 绕开 get back to you 共 11/11 被拒绝。172 次请求均显式关闭 thinking，无非空 reasoning_content。

最终结果在 CSV 的 service-2 分组；设计阶段 310 条和正式服务两轮 334 条合计 644 条全部保留。44 个自动测试及前后端类型检查通过。此次代码已经接入工作区业务入口，尚未部署到线上或手机。

本次正式接入的是云端文本判题。录音转写/长句拆解 UI、知识点列表内对话入口和离线模型仍未在此轮新增；不把它们说成已完成。模型仍可能误判，本次结果是所列样例的回归验证，不是零误判保证。

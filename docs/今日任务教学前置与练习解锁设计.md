# 今日任务「练前教学提示」设计

> 状态：✅ 已实施（2026-08-03 核对）
>
> 定位：在不打断“继续练习”主流程的前提下，把即将用到的教学内容放到用户眼前。

> 当前代码入口：`apps/frontend/src/features/learning/pages/today-task-page.tsx`。实现包含未完成话题去重、教学可用性探测、最多展示 3 项、首次提示 localStorage 标记，以及复用 `PracticeVnDrawer` 展示 `teachingMarkdown`。本文件后续作为交互设计与验收依据，不再作为待开发任务。

## 1. 设计结论

不做强制教学解锁，也不把练习入口改成必须先看 Drawer。

推荐做法是在今日任务顶部的“继续练习”主操作附近，增加一个**练前提示区**：告诉用户“接下来的练习会用到哪些教学”，并给每个话题一个可点击的教学按钮。用户可以先预习，也可以直接继续练习。

```text
今日练习进度
  [继续练习 →]
  接下来的练习会用到这些内容：
  [📖 如何礼貌办理入住] [📖 询问课程信息]
```

它解决的是“用户不知道有教学、也不知道教学与哪道练习有关”，而不是用强制流程去保证用户真的阅读了理论。

## 2. 为什么选择轻提示，而不是强制拦截

- 用户点“继续练习”时，目标通常是马上开口；强制弹 Drawer 会增加一次中断。
- 练习本身就是学习的一部分。教学应该像随手可取的“提示卡”，而不是一道门。
- 当前今日任务已有紧凑、低干扰的卡片式布局；新增一小行关联教学，比新建状态、接口或拦截路由更符合现有产品。
- 无须新增数据库、同步、题目状态或改动抽题和判题链路。

## 3. 页面位置与信息层级

放在今日任务顶部的进度卡内，紧跟“继续练习”按钮之后、状态图例之前。

```text
┌ 今日练习进度                         2/6 ┐
│ ━━━━━━━━━━━                            │
│ [ 继续练习                         → ] │  ← 主操作，维持原样
│                                         │
│  📖 练习前可先看                        │  ← 辅助提示
│  [办理入住的礼貌表达] [问路的关键句]    │  ← 可点教学标签
│                                         │
│  ● 已完成 2    ● 待练习 4              │
└─────────────────────────────────────────┘
```

主操作始终是“继续练习”，教学按钮是与之相邻的辅助动作，不能与主按钮竞争视觉权重。

## 4. 交互规则

### 4.1 显示哪些教学

- 从当前 `plan.steps` 中找出**尚未完成**的题目。
- 按 `topicId` 去重，只展示有 `teachingMarkdown` 的话题。
- 按题目即将出现的顺序排列，而不是按话题名称排序。
- 最多直接展示 3 个；超过时显示 `还有 N 个`，点击后打开一个轻量列表，再选具体教学。
- 若没有可用教学内容，整块不渲染，不留下空白占位。

这样多个练习关联多个教学时，用户能一眼知道“接下来会用到什么”，同时不会被一长串标签淹没。

### 4.2 点击教学按钮

点击任一教学标签：

1. 使用现有 `PracticeVnDrawer` 打开对应 `teachingMarkdown`；
2. Drawer 标题显示“练前教学”，副标题显示对应话题名；
3. Drawer 保持现有关闭方式和 Markdown 呈现；
4. 关闭后回到原位置，不改变当前题目、不启动计时、不记录“已读”。

教学 Drawer 内不必加“我已了解”或“开始练习”按钮。用户关闭后自然回到主按钮继续即可，避免同一个“开始练习”在两个位置出现。

### 4.3 首次使用的差异化提示

第一次进入“有练前教学的今日任务”时，只对提示区做一次温和强调：

- 教学区使用 `primary/[0.06]` 的淡蓝底和 `primary/20` 边框，匹配现有“继续练习”的蓝色语义；
- 书本图标使用主色；
- 第一个教学标签外圈播放一次约 1.5 秒的低透明度蓝色扩散动画，页面打开后即结束；
- 提示文案为：`练习前可先看这些要点，会更容易开口。`

不要使用红点或红色：当前页面把红色用于“逾期”，用户容易将它理解为错误、风险或待处理事项。也不建议一直发光或持续跳动，会抢走“继续练习”的注意力。

首次提示不需要服务端记录。可以用 `localStorage` 保存一个全局的引导键，例如 `manyu:today-teaching-hint-seen`；用户看过一次后，后续回归普通静态样式。即使清除了本地数据，也只是再次看到一次引导，不影响学习数据。

## 5. 视觉细节（对齐当前页面）

当前页的语言是小圆角、低对比 `muted` 背景、蓝色主操作、紧凑 `text-xs / text-[10px]` 信息层级。因此提示区应采用“内嵌信息条”，而非悬浮气泡、角标或大卡片。

建议样式：

| 元素 | 建议样式 |
| --- | --- |
| 容器 | `mt-2.5 rounded-md border border-primary/15 bg-primary/[0.04] px-3 py-2.5` |
| 引导行 | `BookOpen` + `text-[11px] font-medium text-primary` |
| 话题标签 | 白/背景色、细边框、圆角 `rounded-full`，书本小图标 + 单行截断标题 |
| 标签点击态 | `hover:bg-primary/10`、`active:scale-[0.98]`，不使用厚重阴影 |
| 首次强调 | 仅一次 `animate-pulse` 的低透明度 ring；同时尊重 `prefers-reduced-motion` |
| 多项溢出 | 移动端横向滚动或 `还有 N 个`，不要换成两三行挤压进度卡 |

文案建议：

- 默认：`练习前可先看`
- 首次：`练习前可先看这些要点，会更容易开口。`
- 单个按钮：`办理入住的礼貌表达`
- 多项收起：`还有 2 个要点`

避免用“教学”“必看”“未读”等管理式词汇做主要标签；用户更容易理解“要点”和“表达”，也更贴合语言练习场景。

## 6. 最小实现范围

仅改今日任务页及复用 Drawer 的展示参数：

1. 从当前计划的未完成 steps 整理 `upcomingTeachingTopics`（`topicId`、`topicTitle`、出现顺序）。
2. 仅在必要时通过已有 `practiceRepository.getTopicDetail(topicId)` 取教学 Markdown；结果在本页内缓存，避免每次渲染重复请求。
3. 在顶部进度卡的“继续练习”按钮下渲染提示区。
4. 点击标签调用已经存在的 `openTopicTeaching(topicId)`，复用 `PracticeVnDrawer`。
5. 用一个 `localStorage` 布尔值控制首次的单次视觉提示。

不改：

- `continuePractice` / 打开练习 Dialog 的既有行为；
- `daily_practice_runs`、题目抽取、题目排序、练习完成和 AI 判题；
- 后端接口、数据库 schema、离线同步协议；
- 现有“当前话题”列表的直接练习入口。

## 7. 验收标准

1. 有未完成题且关联教学时，顶部“继续练习”下出现对应练前要点。
2. 多个话题去重展示，顺序与接下来题目的出现顺序一致；超过 3 个可访问但不撑高卡片。
3. 点击任意要点打开正确话题的现有教学 Drawer，关闭后不影响练习进度。
4. 点击“继续练习”仍立即进入原有练习流程，没有新增阻拦。
5. 用户首次看到该功能时，提示区有一次性、低干扰的蓝色引导；之后不再持续动画。
6. 无教学内容、离线加载失败或所有题目完成时，不显示误导性的教学按钮。

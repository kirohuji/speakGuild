## 1. 离线模型管理（后台）

后台入口：`/admin/offline-models`（侧栏「离线模型管理」）。仅管理员可准备、导入、验证、发布和删除版本。App 使用登录用户的 `/offline-models/:variantId/manifest` 读取已发布模型。

### 模型与资源

- 覆盖 Whisper Tiny/Base/Small EN q8，以及 MiniLM q8/fp16/fp32。
- 每个型号和版本独立保存，版本号不可重复。仓库下载会先解析并固定实际 commit。
- `OfflineModelVersion.files` 保存相对路径、资产 ID、大小和 SHA-256；完整 ZIP 单独为资产。资源库分类 `offline_model`。
- 下架保留资源引用，允许旧版本重新发布。删除版本先解除引用。

### 准备流程

1. **下载到资源库**：固定白名单 Hugging Face 仓库及来源版本，后台下载并校验。
2. **导入模型包**：选择或上传 ZIP（最大约 600 MB），需保留配置、分词器和 `onnx/` 相对目录。

后台使用 BullMQ `offline-models` 队列，任务类型 `offline-model-prepare`。任务中心可查看进度、取消、重试。重复准备同一版本会拒绝。准备失败不修改当前发布版本。

下载源默认 `https://hf-mirror.com`，可用后端环境变量 `HF_ENDPOINT` 覆盖。

### 发布与验证

发布前核对完整文件清单、资源存在性、大小与校验值；同一型号仅能有一个发布版本。页面独立记录「未验证／通过／失败」；标记失败不能发布。回滚通过重新发布旧版本完成。

### App 安装

原生 App 只向应用后端取发布清单，从资源库资产地址下载，不直连 Hugging Face。配置与权重统一用原生 FileTransfer。

- 完整版本先下到独立临时目录，逐文件校验大小与 SHA-256；整套完成后切换目录，失败恢复原目录。
- SHA-256 用 Filesystem 分块读取，避免大权重进 WebView 内存。
- 安装清单提交后才报告 100%；失败保留原有可用文件。
- **已安装模型不会因进入练习或后台发新版而自动下载。**

### 部署顺序

1. 迁移 `20261114000400_offline_models`，再部署后端和前端。
2. 管理员准备 → 校验 → 记录 iOS 验证 → 手动发布。
3. 用户在 App 模型设置中选择型号下载。

## 2. 练习录音保存与同步

当前流程：

1. 真实录音先保存到本地。iOS：`Directory.Data/user-recordings/<账号>/`；Web：持久化到 SQLite。
2. 同一事务提交录音元数据和 `user_recording` 上传操作，返回稳定的 `user-recording://` 本地身份。
3. 练习回放通过该身份读本地文件。清除下载缓存和学习包**不会**删除录音。
4. 同步答题记录前解析录音依赖：上传文件、创建服务器文件引用，再将本地身份替换为稳定的 `asset://`。失败保留本地文件和待同步操作。
5. 今日任务及学习计划保存记录时，在同一服务器事务中保存文件引用。长句拆解每一级录音也用此机制。
6. 云端转写直接返回资产身份，不再返回用于长期存储的签名 URL。

需要保留录音的练习使用实际录音路径；系统仅转写仍可用于不要求音频文件的文字输入。识别失败后已保存的录音保留在本机。

旧 blob / 过期签名地址无法从地址还原音频时，需单独核对资产，不能直接认定服务器文件已删除。

### iOS 本地模型加载注意

- 配置与权重从已发布清单下载；校验 SHA-256、大小和 JSON。
- 权重先写临时路径，校验通过后安装；全部依赖完整后才发布安装清单。
- Worker 使用原生端读取的配置 JSON；未安装时不把预期缺少的配置文件列为错误。

## 3. 网络提示与界面

网络断开、连接失败和超时使用统一文案及限频提示；后台失败、请求取消和冷却期不重复弹 toast。恢复网络后清除旧请求冷却状态。

知识点练习记录表格隐藏评分列（评分数据保留）。首次读取本地话题时同时读取知识点流程。

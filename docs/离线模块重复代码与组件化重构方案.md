### 2.2 "本地优先 → 远端兜底 → 缓存" 模式（最大重复面）

这是整个离线模块**最核心的重复模式**。每个 repository 的每个数据获取方法几乎都是同样的骨架：

```
┌──────────────────────────────────────────────┐
│  async getXxx(id) {                          │
│    // 1. 检查是否已安装（如有）               │
│    const installed = await checkInstalled()   │
│                                              │
│    // 2. 尝试本地缓存                        │
│    if (installed) {                          │
│      const cached = await localDb.get(...)    │
│      if (cached) return transform(cached)    │
│    }                                         │
│                                              │
│    // 3. 请求远端                            │
│    try {                                     │
│      const remote = await api.getXxx(id)     │
│      await localDb.put(...)  // 缓存         │
│      return remote                           │
│    } catch {                                 │
│      // 4. 降级到缓存（即使过期）            │
│      const cached = await localDb.get(...)   │
│      return cached ?? null                   │
│    }                                         │
│  }                                           │
└──────────────────────────────────────────────┘
```

**建议：** 抽象为泛型 `CachedDataSource<T>` 类：

```ts
// lib/offline/cached-data-source.ts

interface CacheOptions<TLocal, TRemote> {
  /** 本地存储表名 */
  tableName: TableName
  /** 本地数据 → 返回类型的转换 */
  transform: (local: TLocal) => TRemote | null
  /** 远端数据 → 本地存储格式的转换 */
  toCacheFormat: (remote: TRemote) => TLocal & { id: string }
  /** 可选：是否必须先检查安装状态 */
  requireInstalled?: (id: string) => Promise<boolean>
  /** 可选：缓存写入前的额外操作 */
  onCacheWrite?: (remote: TRemote) => Promise<void>
}

class CachedDataSource<TLocal, TRemote> {
  constructor(private opts: CacheOptions<TLocal, TRemote>) {}

  async get(id: string, fetcher: () => Promise<TRemote>): Promise<TRemote | null> {
    // 1. 检查安装状态
    if (this.opts.requireInstalled) {
      const installed = await this.opts.requireInstalled(id)
      if (installed) {
        const cached = await localDb.get<TLocal>(this.opts.tableName, id)
        const result = this.opts.transform(cached!)
        if (result) return result
      }
    }

    // 2. 远端获取
    try {
      const remote = await fetcher()
      await localDb.put(this.opts.tableName, this.opts.toCacheFormat(remote))
      await this.opts.onCacheWrite?.(remote)
      return remote
    } catch {
      // 3. 降级到旧缓存
      const cached = await localDb.get<TLocal>(this.opts.tableName, id)
      return cached ? this.opts.transform(cached) : null
    }
  }
}
```

**使用示例（替换 `getTopicDetail`）：**

```ts
// practice.repository.ts
const topicDetailSource = new CachedDataSource({
  tableName: 'downloaded_unit_details',
  requireInstalled: async (topicId) => {
    // 查找 topic 所属的 pack 是否已安装
    const cached = await localDb.get<{ unitId?: string }>('downloaded_unit_details', `topic:${topicId}`)
    if (!cached?.unitId) return false
    const pack = await localDb.get<{ status?: string }>('downloaded_packs', cached.unitId)
    return pack?.status === 'installed'
  },
  transform: (local) => local.detail ?? null,
  toCacheFormat: (remote) => ({
    id: `topic:${remote.topic.id}`,
    topicId: remote.topic.id,
    detail: remote,
    updatedAt: new Date().toISOString(),
  }),
  onCacheWrite: async (remote) => {
    if (remote.inkScript) {
      await localDb.put('ink_scripts', { id: remote.inkScript.id, topicId: remote.topic.id, ...remote.inkScript, updatedAt: new Date().toISOString() })
    }
  },
})

// 使用
async getTopicDetail(topicId: string): Promise<TopicDetail | null> {
  return topicDetailSource.get(topicId, () => practiceApi.getTopicDetail(topicId))
}
```

**收益：** 每个 repository 的 `get*` 方法从 25-40 行缩到 5-10 行。15 个方法 × 平均减少 25 行 = **~375 行重复逻辑消除**。

### 2.3 `replayItem` 巨型 if-else 链（最需拆分）

**文件：** `offline-sync.service.ts:240-430`，约 200 行

**当前结构：**

```ts
async function replayItem(item: SyncOutboxItem, expressionCache?) {
  if (item.entityType === 'my_unit')          { /* 10行 */ }
  if (item.entityType === 'practice_session')  { /* 30行 */ }
  if (item.entityType === 'practice_turn')     { /* 8行 */ }
  if (item.entityType === 'warmup_records')    { /* 25行 */ }
  if (item.entityType === 'learning_pack')     { /* 2行 */ }
  if (item.entityType === 'daily_practice')    { /* 15行 */ }
  if (item.entityType === 'word_entry')        { /* 15行 */ }
  if (item.entityType === 'chunk_entry')       { /* 15行 */ }
  if (item.entityType === 'pattern_entry')     { /* 15行 */ }
  return false
}
```

**问题：**
- 每新增一种实体类型，函数增长 15-30 行
- 无法单独测试某一种类型的同步逻辑
- `word_entry`/`chunk_entry`/`pattern_entry` 三个分支几乎一模一样（仅 API type 和字段映射不同）
- 在 `flush()` 中又按 bulk/individual 两类分流，逻辑分散在两处

**建议：** 改为注册制 handler 模式：

```ts
// lib/offline/sync-handlers/
//   ├── registry.ts          ← 注册中心
//   ├── my-unit.handler.ts
//   ├── practice-session.handler.ts
//   ├── practice-turn.handler.ts
//   ├── warmup-record.handler.ts
//   ├── expression.handler.ts  ← word/chunk/pattern 三条合一
//   ├── daily-practice.handler.ts
//   └── learning-pack.handler.ts

// registry.ts
export interface SyncHandler {
  entityType: string
  /** 是否支持批量推送（走 /sync/push 批量接口） */
  bulkPushable: boolean
  /** 执行同步 */
  replay(item: SyncOutboxItem, ctx: SyncContext): Promise<SyncResult>
}

const handlers: SyncHandler[] = [
  myUnitHandler,
  practiceSessionHandler,
  practiceTurnHandler,
  warmupRecordHandler,
  expressionHandler,    // 处理 word_entry + chunk_entry + pattern_entry
  dailyPracticeHandler,
  learningPackHandler,
]

// 按 entityType 索引
const handlerMap = new Map(handlers.map(h => [h.entityType, h]))

export function getHandler(entityType: string): SyncHandler | undefined {
  return handlerMap.get(entityType)
}
```

**收益：**
- 新增实体类型只需加一个 handler 文件 + 注册，不改核心同步逻辑
- 每个 handler 可独立单元测试
- `word_entry`/`chunk_entry`/`pattern_entry` 合并为一个 handler，减少 30 行重复
- `flush()` 中的批量/单独分流逻辑从散落各处变为统一在 registry 查询 `handler.bulkPushable`

### 2.4 `applyUserPullChanges` 的机械映射（重复但不复杂）

**文件：** `offline-sync.service.ts:165-240`，约 75 行

```ts
// 当前：6 种类型，每种都是

  await localDb.put('user_progress', {
    id: `scene:${item.sceneId}`,
    type: 'scene',
    remoteId: item.id,
    sceneId: item.sceneId,
    readiness: item.readiness ?? 0,
    mastery: item.mastery ?? 0,
    // ... 10+ 个字段逐个映射
```

**问题：** 6 种类型 × 10-15 个字段 = 大量机械字段映射。每次新增 pull 类型需要写一个新的 for 循环。

**建议：** 声明式映射配置：

```ts
// lib/offline/sync-pull-mappings.ts

interface PullMapping<TItem> {
  /** 服务端返回的数组 key */
  changedKey: string
  /** 本地存储表 */
  tableName: TableName
  /** 生成本地记录 ID */
  localId: (item: TItem) => string
  /** 从服务端数据 → 本地记录（字段映射） */
  mapFields: (item: TItem) => Record<string, unknown>
  /** 可选：写入前校验 */
  validate?: (item: TItem) => boolean
}

const pullMappings: PullMapping<any>[] = [
  {
    changedKey: 'expressionItems',
    tableName: 'expression_entries',
    localId: (item) => item.id,
    mapFields: (item) => ({ /* 字段映射 */ }),
  },
  {
    changedKey: 'sceneProgresses',
    tableName: 'user_progress',
    localId: (item) => `scene:${item.sceneId}`,
    validate: (item) => Boolean(item.sceneId),
    mapFields: (item) => ({
      type: 'scene',
      remoteId: item.id,
      sceneId: item.sceneId,
      readiness: item.readiness ?? 0,
      mastery: item.mastery ?? 0,
      // ...
    }),
  },
  // ... 其余 4 种
]

// 通用 apply 函数
async function applyPullChanges(changed: any, deleted: any) {
  for (const mapping of pullMappings) {
    const items = changed[mapping.changedKey] ?? []
    for (const item of items) {
      if (mapping.validate && !mapping.validate(item)) continue
      await localDb.put(mapping.tableName, {
        id: mapping.localId(item),
        ...mapping.mapFields(item),
        updatedAt: new Date().toISOString(),
        syncStatus: 'synced',
      })
    }
  }
  // deleted 处理同理...
}
```

**收益：** 新增 pull 类型只需加一条配置，不改 apply 逻辑。6 个 for 循环合并为 1 个。

### 2.5 静默 `catch {}` 统一处理（32 处）

**分布统计：**

| 模式 | 数量 | 示例 |
|------|------|------|
| `catch { /* ignore */ }` | 8处 | `asset-cache.service.ts` |
| `catch { return null }` | 9处 | `learning.repository.ts`, `practice.repository.ts` |
| `catch { return defaultValue }` | 5处 | `offline-storage.service.ts` |
| `catch { /* 非关键路径 */ }` | 2处 | `learning.repository.ts:132` |
| 其他静默 | 8处 | 各处 |

**建议：** 统一错误处理 wrapper：

```ts
// lib/offline/error-utils.ts

/**
 * 包装一个可能失败的操作。
 * - onError='ignore': 静默忽略（仅 console.debug）
 * - onError='warn': console.warn + 返回 fallback
 * - onError=fallbackValue: 返回 fallback
 */
export async function safeCall<T>(
  fn: () => Promise<T>,
  options: { scope: string; onError?: 'ignore' | 'warn' | T },
): Promise<T | undefined> {
  try {
    return await fn()
  } catch (error) {
    const msg = `[safe:${options.scope}] ${errorMessage(error)}`
    if (options.onError === 'warn') console.warn(msg)
    else if (options.onError === 'ignore') console.debug(msg)
    if (typeof options.onError !== 'string') return options.onError as T
    return undefined
  }
}

// 使用
const units = await safeCall(() => learningApi.getMyUnits(), {
  scope: 'getMyUnits',
  onError: [], // 返回空数组
})
```

**收益：** 至少知道静默失败发生在哪里。现有很多 `catch { }` 完全没有日志，问题难以排查。

### 2.6 `installUnitFromZip` 资产提取阶段可抽离

**文件：** `learning-pack.service.ts:560-750`，约 190 行

当前资产提取分为两个阶段，内联在一个大方法里：

```text
阶段 A：并行读取 ZIP + 计算 SHA-256（CPU 密集型，可并行）
  for (batch of assetTasks with concurrency=8)
    → readEntryBuffer → digest(SHA256) → verify checksum
    → 收集 AssetResult[]

阶段 B：批量写入文件系统 + SQLite
  for (result of assetResults)
    → 检查 asset_refs 去重
    → filesToSave.push（未缓存的）
    → assetRefsToWrite.push（引用记录）
  → Promise.all(写文件 + 写SQLite引用)
  → Promise.all(写别名)
```

**建议：** 抽离为独立类 `AssetExtractor`：

```ts
// lib/offline/pack-installer/asset-extractor.ts

interface AssetExtractResult {
  ok: boolean
  sha256: string
  buffer: ArrayBuffer
  path: string
  error?: string
}

class AssetExtractor {
  constructor(
    private entries: Map<string, Entry>,
    private checksums: Record<string, string>,
    private concurrency: number = 8,
  ) {}

  /** 阶段 A：并行读取+校验 */
  async extract(assets: AssetRef[], signal?: AbortSignal): Promise<AssetExtractResult[]> { ... }

  /** 阶段 B：去重+写入 */
  async persist(
    results: AssetExtractResult[],
    packId: string,
    onProgress?: AssetWriteProgressHandler,
  ): Promise<{ saved: number; deduped: number; failed: number }> { ... }
}
```

**收益：** `installUnitFromZip` 从 450 行缩到 ~200 行。`AssetExtractor` 可被 `installDelta` 复用（当前 delta 安装的 asset 处理逻辑是手写的另一套）。

## 六、风险评估

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 重构中引入行为差异 | 中 | Phase A 先做（纯函数提取，零行为变化），Phase B/C 逐步 |
| `CachedDataSource` 泛型过于抽象 | 低 | 先替换 2 个方法验证，确认模式稳定再批量替换 |
| handler 注册制初始化顺序 | 低 | 各 handler 无依赖，注册就是 `new Map()` |
| `AssetExtractor` 性能回退 | 低 | 接口与当前一致，只是搬家 |
| `safeCall` 改变异常传播 | 中 | 仅在原本 `catch {}` 的地方使用；有明确错误处理的地方不动 |

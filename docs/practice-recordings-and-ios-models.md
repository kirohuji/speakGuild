# 练习录音、iOS 模型下载与网络反馈

## 录音保存和同步

修复前存在数条不同路径：云端转写返回会过期的 COS 签名地址；本地 STT 返回的音频可能只用临时 blob URL 表示；系统仅转写模式不返回音频；场景录音上传失败后没有持久补传机制。知识点记录中的音频又存于 JSON，缺少文件引用保护。

当前流程：

1. 真实录音先保存到本地。iOS 使用 `Directory.Data/user-recordings/<账号>/`，网页将录音内容持久化到 SQLite。
2. 在同一事务中提交录音元数据和 `user_recording` 上传操作，返回稳定的 `user-recording://` 本地身份。
3. 练习回放通过该身份读取本地文件。清除下载缓存和学习包不会删除录音。
4. 同步答题记录前解析录音依赖：上传文件、创建服务器文件引用，然后将本地身份替换为稳定的 `asset://` 引用。失败保留本地文件和待同步操作，不能将答题记录误报为已交付。
5. 今日任务及学习计划保存记录时，在同一个服务器事务中保存文件引用，避免被未引用资源清理误删。长句拆解的每一级录音也使用此机制。
6. 云端转写直接返回资产身份，不再返回用于长期存储的签名 URL。

需要保留录音的练习使用实际录音路径，系统仅转写仍可用于不要求音频文件的文字输入。识别失败后已经保存的录音保留在本机，可以输入文字继续。

这些修改保护后续录音。只有已经失效的 blob 地址、没有保存实际音频的旧记录，无法从地址还原音频。旧签名地址失效不一定表示服务器文件已删除，需要单独核对资产，不能直接认定数据已丢失。

## iOS 本地模型

- 配置与权重从后台已发布的资源清单下载，统一使用原生 FileTransfer 保留原始字节；校验 SHA-256、大小和 JSON 格式。
- 权重使用原生文件下载。文件先写入临时路径，检查非空及基本大小，校验通过后安装；重试失败保留原先可用的文件。
- 全部依赖完整后才发布安装清单，安装状态核对清单中的大小。缺少任意文件不能标记安装成功。
- Worker 使用原生端读取的配置 JSON，模型重装后更新加载版本，初始化失败可重试。
- 未安装时不将预期缺少的配置文件列为错误；部分安装失败显示继续修复提示。

目前通过模拟 iOS 原生插件的测试验证下载和校验流程，未执行 iOS 真机下载或推理验收。

## 网络提示和界面

网络断开、连接失败和超时使用统一文案及限频提示；后台失败、请求取消和冷却期不重复弹 toast。业务校验错误仍正常显示。恢复网络后清除旧请求冷却状态。

知识点练习记录表格隐藏评分列，评分数据保留。首次读取本地话题时同时读取知识点流程，按钮不再依赖先进入场景练习才出现。

验证使用类型检查和单元／SQLite 回归测试，不执行 build 或浏览器操作。

## 二、规格实况（重要）

所有 17 张图的实际规格一致：

| 项目 | 实测值 |
|---|---|
| 尺寸 | **512 × 768**（2:3） |
| 格式 | PNG，8-bit RGBA（带透明通道） |
| 构图 | 半身，`half_body / cropped_at_waist / front_view`，正面朝镜头 |
| 体积 | 单张 500–740 KB |
| 用途 | 同时充当 **头像 + 立绘**（`avatarUrl` 与 `spriteBaseUrl` 指向同一张） |

这与 `00-规范` 里原先写的「1080×1920 全身立绘」不符，**以实测为准**：现阶段的美术管线就是 512×768 半身像。规范已改为「半身 512×768 为默认，1080×1920 全身为可选进阶」。

## 三、数据库现状（用之前必须知道）

| 字段 | 现状 |
|---|---|
| `avatarUrl` | 18 个角色都填了（除 Emma 外均为 `asset://`） |
| `spriteBaseUrl` | **只有 `fox` 填了**，且与头像同一张图；其余 17 个为 `null` |
| `expressions` | 只有 `fox` 与 `emma` 各有一条 `default`；其余 16 个为空 `{}` |

也就是说：**「立绘已收集」实际是「默认半身像已收集」**。表情差分（`happy / thinking / surprised / sad`）与真正的立绘分层尚未入库。

### 需要修的三件事

1. **Iris 与 Sari 共用一张图** —— 已在资源包里用复制件占位，但必须替换 Iris 的独立形象，否则玩家第一章就会把两人混淆。
2. **`spriteBaseUrl` 大面积为空** —— 探索模式的 VN 渲染依赖它落位，建议一次性把 18 个角色的 `spriteBaseUrl` 指到各自的 `default`。
3. **`expressions` 只有 1 档** —— 至少补齐 `default / happy / thinking`，否则台词只能一个表情播到底。

## 四、在剧本与资源里怎么引用

- 资源包里只存**别名**：`chr_fox_default`、`avatar_fox`。
- 数据库里存 **`asset://<fileAssetId>`**（现有做法是对的），**不要**把带 `q-signature` 的 COS 签名 URL 写进剧本或 `expressions`——签名会过期。
- Ink 里仍然只写 `# speaker:fox` + `# expression:happy`，具体是哪张图由 `expressions.happy` 决定，剧本不感知文件。

## 五、头像要不要单独出一版

现状是「一张半身像兼任头像」，在圆形头像框里会露出肩膀和尾巴，观感还行但不够聚焦。

建议：

| 方案 | 成本 | 建议 |
|---|---|---|
| 直接复用半身像 | 0 | **现阶段先用这个** |
| 从半身像裁 512×512 头部特写 | 低（脚本批处理） | 有空就做，观感提升明显 |
| 单独重绘头像 | 高 | 不建议，性价比低 |

若要裁切，注意保留耳朵与发梢，头部不要顶到画布边缘。

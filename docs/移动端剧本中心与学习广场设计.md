# 漫语町移动端剧本中心与学习广场设计

> 目标：在移动端底部导航新增「剧本」，承载剧情包商店、我的剧本、练习记录、VN / 跟读体验、视频作品与学习广场。  
> 设计原则：剧情包与学习包复用内容和离线基础设施，但保持独立的产品入口、进度语义和沉浸体验。  
> 本文只定义产品、交互、页面与数据边界，不直接修改现有实现。

---

## 一、核心结论

底部导航新增一个「剧本」即可，不再增加独立「广场」入口。

```text
首页｜今日任务｜学习计划｜剧本｜我的词库
```

「剧本」首页内部使用两个一级 Tab：

```text
剧本
├── 我的
│   ├── 正在练习
│   ├── 最近记录
│   ├── 我的作品
│   └── 已加入的剧本
└── 广场
    ├── 关注/推荐流（MVP 只做推荐）
    ├── VN 视频
    ├── 跟读视频
    └── 学习进度动态
```

推荐默认进入「我的」，而不是广场。剧本的首要价值仍然是沉浸式学习与练习，广场负责展示成果、提供继续练习的动力，而不是把产品变成泛内容社区。

剧本商店与全部练习记录沿用学习计划现有的移动端操作习惯，放在 Header 右上角：

- 商店图标：打开「剧本商店」全高 Drawer/Dialog；
- 记录图标：打开「练习记录」全高 Drawer/Dialog；
- 如果存在下载、更新或卸载任务，商店/任务图标显示状态圆点或进度提示；
- 两者都不是一级 Tab，也不默认进行页面路由跳转。

---

## 二、产品定位

### 2.1 剧本不是另一个学习计划

学习计划解决：

> 今天应该学什么，以及如何按知识路径持续推进。

剧本解决：

> 我想进入一个故事，在角色和情境中开口，并留下可以回看、生成和分享的作品。

二者可以共享单词、句块、句型、音频、离线包和学习进度基础能力，但用户心智必须不同：

| 学习计划 | 剧本 |
|---|---|
| 课程、任务、掌握度 | 故事、角色、章节、作品 |
| 以知识路径为主 | 以情节和沉浸体验为主 |
| 完成训练单元 | 推进剧情并完成表演 |
| 学习记录 | 游玩记录 + 表演作品 |
| 学习包商店 | 剧本商店 |

### 2.2 剧本中心的核心闭环

```text
发现剧本
  → 下载/加入我的剧本
  → 进入章节
  → 选择 VN 或跟读模式
  → 完成练习
  → 保存练习记录
  → 可选生成视频
  → 私密保存或发布到广场
  → 从作品返回原剧本继续练习
```

视频不是额外的娱乐功能，而是练习结果的一种可视化载体。即使用户不发布，视频也应作为个人学习档案长期保留。

## 三、整体信息架构

### 3.1 路由建议

```text
/scripts                         剧本首页
/scripts?tab=mine                我的
/scripts?tab=square              广场
/scripts/packages/:packageId     剧本详情
/scripts/packages/:packageId/episodes/:episodeId
                                 章节详情/模式选择
/scripts/records/:recordId       练习记录详情
/scripts/works                   我的作品
/scripts/works/:workId           作品详情/发布设置
/scripts/posts/:postId           广场动态详情（无评论）
/scripts/player/:episodeId       VN 或跟读沉浸播放器
```

进入 `/scripts/player/*` 时开启现有 `immersiveMode`，隐藏 Header 和 BottomNav；退出后返回章节详情或原来的剧本进度位置。

「剧本商店」和「全部练习记录」默认由 `/scripts` 页面内部的受控 Drawer/Dialog 承载，不要求独立路由。为了支持系统通知、深链和恢复现场，可以使用查询参数表达打开状态：

```text
/scripts?panel=store
/scripts?panel=records
```

关闭面板后移除 `panel`，仍停留在原来的「我的 / 广场」Tab 和滚动位置。

### 3.2 页面层级

```text
底部「剧本」
│
├─ 我的
│  ├─ Header：商店 / 练习记录图标
│  ├─ Hero：继续正在练习的剧本
│  ├─ 最近练习
│  ├─ 我的作品
│  ├─ 已加入的剧本
│  └─ 已加入的剧本
│
├─ 广场
│  ├─ 推荐流
│  ├─ 内容筛选
│  └─ 动态卡片/视频播放器
│
├─ 剧本详情
│  ├─ 剧情简介与角色
│  ├─ 学习收益
│  ├─ 单词/句块/句型
│  ├─ 章节目录
│  └─ 下载/开始/继续
│
└─ 练习与作品
   ├─ VN 模式
   ├─ 跟读模式
   ├─ 练习结果
   ├─ 生成视频
   └─ 保存/发布
```

### 3.3 与学习计划一致的三级浏览层级

剧本沿用学习计划已有的“包 → 内容叶子 → 练习”浏览心智，只替换内容语义：

| 层级 | 学习计划 | 剧本 |
|---|---|---|
| 一级 | 学习计划首页 | 剧本首页「我的 / 广场」 |
| 二级 | 学习包详情 | 剧本包详情 |
| 三级 | 练习话题详情 | 章节详情 |
| 沉浸层 | 话题输出练习 / VN | 章节 VN / 跟读 |

因此移动端实现上，剧本包详情可以复用 `LearningUnitPage` 的页面骨架、返回方式、Header、资源区和列表交互；原来的 `TrainingTopic` 列表位置替换成 `StoryEpisode` 章节列表。

```text
学习包详情
├── 包介绍
├── 学习目标
├── 练习话题 List
├── 单词 / 句块 / 句型
└── 开始话题练习

剧本包详情
├── 剧情介绍
├── 角色与故事目标
├── 章节 List
├── 单词 / 句块 / 句型
└── 进入章节
```

这里的“保持一致”包括：

- 二、三级页面的返回导航；
- Header 高度和安全区；
- 页面内容宽度和左右间距；
- 加载、空态、锁定、下载、更新状态；
- 内容区块标题和展开方式；
- 单词、句块、句型的详情与收藏能力；
- 进入沉浸练习后隐藏 BottomNav；
- 退出练习后回到原剧本和原章节位置。

不要求一致的是课程语义：剧本不显示“今日任务、题数、知识点达标”等课程式信息。

## 四、「我的」Tab 设计

### 4.1 页面目标

用户进入后，3 秒内要知道：

1. 我正在练哪个剧本；
2. 上次练到了哪里；
3. 现在点哪里可以继续；
4. 最近留下了什么记录或作品；
5. 没有剧本时去哪里获取。

### 4.2 页面布局

```text
┌──────────────────────────────┐
│ 剧本                [我的｜广场] │
├──────────────────────────────┤
│ 继续演出                         │
│ ┌──────────────────────────┐ │
│ │ 剧本封面 + 当前角色氛围图       │ │
│ │ 《雨夜便利店》 第 3 章          │ │
│ │ 进度 42% · 上次使用 VN 模式    │ │
│ │ [继续剧情]       [切换跟读]     │ │
│ └──────────────────────────┘ │
│                                  │
│ 最近练习                         │
│ [记录卡] [记录卡] 横向滑动         │
│                                  │
│ 我的作品                    [全部] │
│ [视频封面] [视频封面] 横向滑动     │
│                                  │
│ 我的剧本                    [管理] │
│ [剧本卡] [剧本卡]                  │
│                                  │
└──────────────────────────────┘
```

Header 与现有 `LearningPlanPage` 对齐：

```text
                         [任务状态] [记录] [商店]
                  [   我的   ｜   广场   ]
```

- 页面容器直接复用 `mx-auto max-w-2xl px-4 pb-24 pt-3`；
- 第一行复用 `mb-3 flex items-center justify-between`；
- 左侧不增加移动端大标题，保持与学习计划一致的留白；
- 右侧按钮组复用圆形玻璃胶囊：
  `rounded-full bg-background/36 p-1 backdrop-blur-2xl ring-1 ring-white/45`；
- 每个图标按钮复用 `size-9` 点击区域与 `size-[18px]` 图标；
- 顺序与学习计划一致：下载任务状态 → 练习记录 → 剧本商店；
- 「我的 / 广场」Tabs 放在按钮行下方，作为页面内容模式切换，不塞进右侧图标胶囊；
- Tabs 使用现有 shadcn `Tabs` 视觉 token，不另外设计新的分段控件；
- 「记录」使用 History/Clock 图标；
- 「商店」使用 Store/ShoppingBag 图标；
- 图标按钮提供无障碍名称和足够点击区域；
- 切到「广场」后 Header 图标仍保留，用户无需先切回「我的」；
- Drawer/Dialog 打开时保留当前 Tab 与列表滚动位置。

### 4.3 正在练习

首页只突出一个“最近活跃剧本”，避免同时出现多个强 CTA。

卡片信息：

- 剧本封面、名称、主题氛围；
- 当前章节与剧情节点；
- 总体进度；
- 当前扮演角色；
- 上次练习时间；
- 上次模式：VN / 跟读；
- 主按钮「继续剧情」；
- 次操作「切换跟读」或「章节目录」。

如果用户有多个进行中的剧本，可左右滑动或点击「全部剧本」，但默认只展示最近一个。

### 4.4 最近练习

练习记录与视频作品必须区分：

- **练习记录**：每次 VN 或跟读 session 都产生，记录真实训练过程；
- **视频作品**：用户基于某次练习主动生成，可以私密保存或发布。

记录卡建议展示：

- 来源剧本与章节；
- 模式图标；
- 练习时长；
- 完成度、跟读评分或有效开口轮数；
- 本次使用的核心表达；
- 是否已生成视频；
- 「查看复盘」与「生成视频」。

### 4.5 我的作品

作品卡采用视频封面，不使用普通学习数据卡片：

- 9:16 或 16:9 封面；
- VN / 跟读角标；
- 时长；
- 私密 / 已发布状态；
- 点赞数（仅已发布显示）；
- 渲染中、失败、可发布等状态。

首页只显示最近 3～5 个作品，完整管理放入「我的作品」。

### 4.6 空状态

首次进入不能同时给出多个空模块。统一为一个有故事感的引导：

> 选择你的第一部剧本。  
> 进入角色、开口完成一段剧情，并留下第一支英语作品。

主按钮：「打开剧本商店」，点击后打开 Header 对应的商店 Drawer/Dialog。  
次按钮：「体验免费短剧」

## 五、剧本商店 Drawer/Dialog

### 5.1 商店入口

主入口固定为剧本页 Header 右上角的商店图标。以下位置可以作为快捷入口，但都打开同一个商店 Drawer/Dialog：

- 「我的」空状态；
- 广场动态中的「查看同款剧本」；
- 剧本完成页的「下一部剧本」。

这样既与学习计划保持一致，也避免商店成为额外导航层。

### 5.2 容器与关闭行为

- 移动端直接对齐学习计划商店 Drawer：
  `max-h-[88vh] rounded-t-[28px] border-0 bg-background`；
- Header 复用 `px-4 pb-1 pt-2 text-left`；
- 标题复用 `text-base font-semibold`；
- 内容区复用 `h-[calc(88vh-4rem)] overflow-x-hidden px-4 pb-[calc(1rem+env(safe-area-inset-bottom,0px))]`；
- 商店内容独立滚动，底部遵守安全区；
- 点击剧本卡进入剧本详情时关闭商店面板并导航到详情页；
- 从详情返回时回到 `/scripts`，可以恢复之前的 Tab；
- 关闭面板只关闭商店，不改变「我的 / 广场」选择与页面滚动位置。

### 5.3 商店首屏

```text
顶部：返回｜剧本商店｜搜索
主题策展 Banner：本周新剧 / 免费体验
分类 Chips：全部、校园、职场、旅行、日常、悬疑……
精选剧本：大封面横滑
适合你的：双列卡片
短剧体验：低门槛列表
```

剧本商店不应完全复制学习包商店的视觉。学习包强调结构与知识量，剧本商店应强调封面、人物关系、冲突和情绪。

### 5.4 剧本卡片

主要展示：

- 封面；
- 剧本名与一句钩子；
- 难度；
- 预计完成时长；
- 章节数；
- 支持模式：VN、跟读、视频；
- 免费/会员/单独解锁状态；
- 已下载、可更新等离线状态。

单词数、句块数、句型数不放在商店卡片首层，避免破坏沉浸感；这些信息放在详情页的「你将学会」中。

## 六、剧本详情

### 6.1 详情页顺序

```text
沉浸式封面 Hero
→ 剧情钩子
→ 继续/下载/开始按钮
→ 角色与关系
→ 你将练会什么
→ 章节目录
→ 单词、句块、句型
→ 包体、版本、离线状态
```

不要先展示资源统计和下载按钮。用户应该先被故事吸引，再理解它能练到什么。

### 6.2 Hero 区

- 全宽封面或场景背景；
- 深色渐变保证文字可读；
- 剧本名、一句话简介、类型标签；
- 难度、章节数、总时长；
- 当前进度；
- 固定主 CTA：
  - 未加入：「加入并下载」；
  - 已下载未开始：「开始第一章」；
  - 进行中：「继续第 N 章」；
  - 已完成：「再次体验」。

### 6.3 「你将练会什么」

剧情包虽然沉浸，但仍必须证明学习价值。该区域按结果表达，不直接堆资源数量：

```text
完成本剧本后，你将能够：
· 在便利店询问商品和付款方式
· 用委婉语气寻求帮助
· 在突发情况下解释自己的需求
```

其后再提供可展开资源：

- 核心单词；
- 高频句块；
- 关键句型；
- 可收藏到表达库；
- 已掌握/待复练状态。

### 6.4 章节目录

章节目录直接替换学习包详情中的“练习话题 List”，不再额外创造一套剧集导航组件。列表可以复用原有行高、圆角、锁定状态、进度条和进入箭头，再将内容字段映射为章节语义。

每章展示：

- 章节名与一句情节摘要；
- 解锁状态；
- VN / 跟读模式可用性；
- 最佳练习成绩；
- 是否产生作品；
- 下载状态；
- 「继续」「重练」「查看记录」。

未解锁章节可以显示条件，但不要暴露剧情剧透。

### 6.5 二级详情页与今日任务的边界

剧情包不加入学习计划的今日任务内容池：

- 不调用今日任务生成逻辑；
- 不从章节抽取 Warmup；
- 不把章节完成状态计入今日任务完成度；
- 不因为今日任务未完成而锁定剧情；
- 不把剧本包加入“最多 3 个未完成学习单元”的限制；
- 剧本进度由用户主动进入剧本中心推进；
- 首页如需提醒，只能作为“继续剧情”的独立推荐，不伪装成今日任务。

单词、句块、句型仍可被收藏到表达库，也可以进入通用复习调度；这是学习资产复用，不代表剧本与今日任务绑定。

## 七、章节详情与练习模式

### 7.1 章节详情是三级页面

章节详情对应学习计划中的“练习话题详情”，但不承担完整教学流水线。它的职责是帮助用户理解本章发生什么、自己扮演谁、需要如何开口，然后进入 VN 或跟读。

推荐结构：

```text
Header：返回剧本详情 + 章节名称
剧情梗概
本章场景与出场角色
用户扮演的角色/本章目标
本章关键表达
VN / 跟读模式入口
历史最佳记录（如果存在）
```

### 7.2 章节教学区

章节教学区只提供“开演前说明”，不做练习题：

- **剧情梗概**：说明上一章衔接、本章冲突与任务，不剧透结局；
- **场景说明**：时间、地点和当前情境；
- **角色说明**：出场人物、关系和用户扮演对象；
- **表达意图**：本章需要完成的沟通目标；
- **关键表达**：3～8 个本章会出现的单词、句块或句型；
- **模式说明**：VN 是主动回答，跟读是模仿与完整演出。

不包含：

- Warmup 题目；
- Prime / Build / Recall / Speed 流水线；
- 今日任务状态；
- 今日复练数量；
- 知识点达标门槛；
- 强制完成教学后才能进入剧情。

用户可以直接开始剧情；关键表达只是可展开的预览和准备材料。

### 7.3 进入章节前

```text
章节场景图
剧情梗概与预计时间
本章角色
核心表达 3～5 个

[VN 互动模式]
你决定如何回答，推进剧情

[跟读剧场]
跟随角色台词完成配音与模仿
```

系统记住用户上次模式，下次将其作为主按钮，但始终允许切换。

### 7.4 VN 互动模式

定位：用户作为角色主动回答，选择或说出自己的表达，推进剧情。

记录内容：

- 进入和退出时间；
- 完成的节点与选择；
- 用户语音、转写文本；
- AI 反馈与重说记录；
- 使用的单词、句块、句型；
- 完成度；
- 可回放的剧情时间轴；
- 视频渲染所需的角色、背景、字幕、语音快照。

### 7.5 跟读模式

定位：用户跟随角色台词进行听、模仿、录制和复演。

推荐节奏：

```text
听原声
→ 看字幕跟读
→ 弱化字幕再读
→ 只看中文意图或场景提示
→ 完整角色演出
```

每句记录：

- 原声；
- 用户录音；
- 转写；
- 完整度；
- 发音/节奏/流利度提示；
- 重录次数；
- 最佳 take。

完成后用户可以选择最佳 take 生成一支完整跟读视频。

### 7.6 沉浸原则

练习过程中：

- 隐藏底部导航；
- 不出现商店、广场、会员中心等跳出入口；
- UI 优先展示角色、场景、台词和录音状态；
- 学习反馈以场景内轻提示呈现；
- 详细评分放到结束复盘；
- 自动保存节点，异常退出后可继续。

### 7.7 章节练习粒度

章节是最合适的练习、记录和分享单位。一章应当能够在一次移动端 session 中完成，不建议把一个章节设计成二三十分钟的长流程。

推荐剂量：

| 内容 | 建议范围 |
|---|---|
| 单章完整体验 | 6～12 分钟 |
| 核心剧情节点 | 1 个 |
| 用户有效开口 | 6～12 轮 |
| 关键表达 | 3～8 个 |
| 跟读台词 | 6～15 句 |
| 可分享成片 | 15～90 秒 |

如果剧情内容较长，应拆成多章或多幕，而不是要求用户一次完成。章节拆分点优先选择：

- 场景切换；
- 对话目标变化；
- 新角色进入；
- 一个冲突解决；
- 用户作出关键选择；
- 出现适合复盘的情绪或剧情停顿。

### 7.8 单章练习闭环

每章建议遵循：

```text
1. 看梗概
   了解角色、场景和本章目标

2. 预览关键表达
   只看 3～8 个表达，不做 Warmup

3. 完成 VN 或跟读
   用户可以自由选择模式

4. 查看章节复盘
   剧情结果、开口表现、关键表达、可重说句子

5. 可选再演一次
   切换模式或针对薄弱台词重练

6. 保存章节记录
   可生成章节视频并选择是否发布

7. 继续下一章
```

第一次体验不强制用户同时完成 VN 和跟读。建议：

- 用户任选一种模式即可完成章节主进度；
- 另一种模式标记为“再演一次”，作为强化练习；
- VN 与跟读分别保留最佳记录；
- 两种模式都完成后，可以授予“完整演出”状态或额外成就；
- 章节解锁下一章主要依据剧情顺序，不以口语评分作为硬门槛。

### 7.9 两种模式的互补关系

| VN | 跟读 |
|---|---|
| 主动组织表达 | 模仿自然表达 |
| 允许不同回答与选择 | 围绕固定台词练声音 |
| 训练沟通与临场反应 | 训练发音、节奏和语调 |
| 记录剧情选择和用户回答 | 记录逐句最佳 take |
| 视频突出互动剧情 | 视频突出角色配音 |

推荐引导顺序不是强制顺序：

```text
初级用户：跟读 → VN
中高级用户：VN → 针对薄弱片段跟读
复练用户：直接进入上次薄弱台词或最佳模式
```

系统可以根据用户水平推荐默认模式，但必须允许用户立即切换。

## 八、练习记录与视频作品

### 8.1 练习记录 Drawer/Dialog

「最近练习」仍在「我的」首页提供少量摘要；全部记录通过 Header 右上角的记录图标打开，不单独占用一级页面入口。

面板结构：

```text
练习记录
[全部｜VN｜跟读]

今天
  记录卡
  记录卡
更早
  记录卡
```

每条记录支持：

- 查看复盘；
- 回到对应剧本和章节；
- 继续未完成练习；
- 生成视频；
- 查看已经派生的视频作品。

点击记录进入记录详情时关闭面板并进入详情页；从详情返回 `/scripts?panel=records` 时可以重新打开记录面板并恢复列表位置。

记录面板直接对齐学习计划练习记录 Drawer：

- `h-[95vh] max-h-[95vh]`；
- `rounded-t-[28px] border-border/70 bg-background drawer-surface`；
- Header 使用 `px-4 pb-1 pt-2 text-left`；
- 内容区使用 `min-h-0 flex-1 overflow-hidden px-4 pb-[calc(1rem+env(safe-area-inset-bottom,0px))]`；
- 内部 `全部 / VN / 跟读` 使用现有 `TabsList + TabsTrigger`；
- 打开某条记录的完整回放/复盘时，再切换为现有记录详情使用的 `100dvh` 全屏 Drawer。

### 8.2 练习结束页

顺序建议：

```text
完成反馈
→ 本次剧情结果
→ 开口与表达复盘
→ 可立即重说的薄弱句
→ 保存的单词/句块/句型
→ 生成视频
→ 发布到广场（次要）
→ 继续下一章
```

「继续下一章」与「查看复盘」优先级高于「发布」，避免社区行为反客为主。

### 8.3 视频生成

VN 和跟读都支持生成视频，但模板不同：

| 类型 | 视频表现 |
|---|---|
| VN 视频 | 场景、角色、用户选择/回答、字幕、剧情推进 |
| 跟读视频 | 原角色画面、用户最佳配音、双语/单语字幕、评分结尾卡 |

生成流程：

```text
选择片段/最佳 take
→ 选择字幕与封面
→ 预览
→ 后台渲染
→ 保存到我的作品
→ 可选发布
```

长视频渲染必须异步处理。用户离开页面后继续生成，通过站内通知告知成功或失败。

### 8.4 作品状态

```text
draft       草稿
rendering   生成中
ready       已生成、仅自己可见
published   已发布
failed      生成失败、可重试
hidden      因审核或用户操作下架
```

练习记录不可因为视频删除而删除；视频只是记录的派生内容。

### 8.5 隐私默认值

- 练习记录默认私密；
- 新生成作品默认「仅自己可见」；
- 发布必须由用户主动确认；
- 发布前可预览公开昵称、头像、字幕、语音与封面；
- 删除广场动态不删除本地/云端练习记录；
- 用户可以单独删除作品文件。

### 8.6 分享粒度：以章节作品为主

用户不直接“分享整个剧本包”，而是分享自己在某一章节中的学习成果。

```text
剧本包
├── 第 1 章
│   ├── VN 练习记录
│   ├── 跟读练习记录
│   └── 用户章节作品 ← 主要分享单位
├── 第 2 章
│   └── 用户章节作品
└── 整包完成
    └── 完成里程碑/作品合集 ← 可分享，但不重新发布完整剧情
```

章节作品可以是：

- 本章完整跟读演出；
- 本章 VN 互动过程的精选片段；
- 用户选择的 15～90 秒精彩片段；
- 本章完成卡；
- 本章掌握表达与开口时长总结。

广场动态必须关联：

```text
sceneId       剧本包
episodeId     章节
recordId      原始练习记录
workId        派生视频作品
mode          vn | shadowing
```

分享卡展示“来自《剧本名》· 第 N 章”，但不能让其他用户直接获取完整剧本文件、全部章节台词或原始资源。

整包完成时可以分享：

- 剧本完成里程碑；
- 总开口时间；
- 完成章节数；
- 掌握表达数；
- 用户主动选出的章节作品合集；
- 「去练同款」入口。

整包分享不自动拼接所有章节视频，也不暴露完整剧情。这样可以控制视频长度、减少剧透，并保持剧本内容与用户生成作品之间的边界。

## 九、广场设计

### 9.1 广场定位

广场是“学习成果流”，不是社交讨论区。

允许发布：

- VN 剧情视频；
- 跟读作品；
- 学习里程碑；
- 剧本完成记录；
- 连续练习、掌握表达等系统生成进度卡。

不提供：

- 自由图文发帖；
- 评论区；
- 私信；
- 转发链；
- 热搜和争议榜单。

这样既能产生陪伴感和展示感，也能显著降低社区治理与未成年人安全成本。

### 9.2 页面结构

顶部保留「我的 / 广场」切换，广场内部使用轻量筛选：

```text
推荐｜跟读｜VN｜进步
```

MVP 不做「关注」关系和关注流。先通过推荐流验证用户是否愿意观看、点赞、发送快捷鼓励以及从作品进入同款剧本。

### 9.3 Feed 交互

采用 Twitter 风格的虚拟无限滚动 List，而不是全屏短视频上下翻页：

- 一次可感知前后动态；
- 视频进入可视区域后静音预览；
- 点击后进入卡片内播放或详情页；
- 离开可视区域自动暂停；
- 保留滚动位置；
- 分页游标加载；
- 可变高度虚拟列表；
- 视频封面优先，避免滚动时同时初始化多个播放器。

不建议直接做抖音式全屏视频流，因为剧本中心仍是学习产品，信息流中还包含进度卡与学习上下文。

### 9.4 动态卡片

视频动态：

```text
头像 昵称 · 学习等级/连续天数
作品标题或系统文案
视频播放器/封面
《剧本名》· 第 N 章 · VN/跟读
本次练习：时长、核心表达、完成度
[点赞] [快捷鼓励] [练同款]
```

学习进度动态：

```text
用户完成《雨夜便利店》
累计开口 36 分钟
掌握 12 个新表达
[点赞] [太棒了/继续加油/我也在练] [查看剧本]
```

### 9.5 快捷语

没有评论区，快捷语采用预设鼓励：

- 太棒了；
- 发音真自然；
- 剧情感拉满；
- 我也在练；
- 继续加油；
- 学到了。

一次动态每个用户只能发送一种快捷语，可切换或取消。前端聚合显示：

> 12 人说“太棒了” · 5 人说“我也在练”

快捷语不是自由文本，从源头降低审核压力。

### 9.6 从广场回到学习

每条内容都必须能回到学习闭环：

- 「练同款」进入对应剧本详情或免费体验；
- 已拥有该剧本时进入相同章节；
- 未解锁时展示剧本详情与解锁条件；
- 可收藏作品中的核心表达；
- 不允许广场成为无法回流练习的独立流量黑洞。

## 十、与学习计划的对齐方式

整体操作逻辑可以与学习计划保持一致，但只对齐骨架，不机械复制视觉和术语。

| 学习计划 | 剧本中心 |
|---|---|
| 我的学习 | 我的剧本 |
| 学习包商店 Drawer/Dialog | 剧本商店 Drawer/Dialog |
| 当前学习单元 | 正在练习的剧本 |
| 今日任务记录 Drawer/Dialog | 剧本练习记录 Drawer/Dialog |
| 单元详情 | 剧本详情 |
| 练习话题 List | 章节 List |
| 练习话题详情 | 章节详情/开演准备 |
| 输出练习 | VN / 跟读 |
| 学习结果 | 练习复盘/视频作品 |

应该复用：

- 商店、已加入、下载、更新和卸载的状态机；
- zip、manifest、checksum、增量更新；
- SQLite 离线内容；
- 单词、句块、句型与音频资源；
- 权限与会员判断；
- 下载任务 Drawer；
- 进度同步与 outbox；
- 详情页的资源查看能力。

不应该直接复用：

- 学习计划的卡片文案；
- 今日任务的任务感；
- `UserSceneProgress` 的全部语义；
- 学习包完成度算法；
- 课程式章节视觉；
- 普通学习记录作为视频作品模型。

### 10.1 与今日任务的明确隔离

```text
学习计划
  → TrainingTopic
  → Warmup / 输出练习
  → 今日任务

剧本中心
  → StoryEpisode
  → 章节梗概 / 角色 / 关键表达
  → VN / 跟读
  → 剧本练习记录 / 视频作品
```

二者共享内容资产和练习基础能力，但不共享每日调度：

- `TrainingTopic` 可以进入今日任务；
- `StoryEpisode` 不进入今日任务；
- 剧本章节不会被 TodayTaskPage 读取；
- 剧本练习不会改变今日任务的完成状态；
- 剧本练习产生的表达收藏可以进入表达库的通用复习；
- 剧本中心使用自己的最近练习、连续剧情和章节进度驱动回访。

## 十一、数据与离线边界

### 11.1 内容包复用

剧情包继续使用 `LearningPackage` / zip / manifest 基础设施，并通过 `packageType=story` 区分。包内可以复用：

- Scene；
- StoryEpisode；
- InkScript；
- Vocabulary；
- Chunk；
- SentencePattern；
- 角色、背景、立绘、音频；
- VN 时间轴与跟读 variant；
- 视频渲染需要的静态资源。

剧情包与学习包不能仅靠标题、目录或前端筛选判断类型，所有接口必须按 `packageType=story` 查询。

### 11.2 本地存储建议

共享底层表但使用明确的类型和索引：

```text
downloaded_packs
  - packId
  - packageType: learning | story
  - manifest
  - version
  - status

downloaded_story_episodes
  - episodeId
  - sceneId
  - inkPayload
  - variantPayload

story_progress
  - sceneId
  - episodeId
  - nodeId
  - mode
  - updatedAt

story_practice_records
  - recordId
  - sceneId
  - episodeId
  - mode
  - resultSnapshot
  - syncStatus
```

是否新建 SQLite 表由实现阶段结合现有 schema 决定，但产品层必须保证学习进度与剧情进度可分别查询和恢复。

### 11.3 离线行为

离线可用：

- 查看已下载剧本；
- VN 剧情播放；
- 已打包的 TTS/音频；
- 跟读录音与本地回放；
- 查看本地练习记录；
- 保存进度到 outbox。

需要联网：

- AI 自由回答判断；
- 云端 STT/TTS（无本地替代时）；
- 视频云渲染；
- 发布、点赞、快捷语；
- 广场 Feed；
- 商店最新状态与购买。

离线完成的练习应先保存记录，再在联网后同步；不能因为视频生成或发布失败而丢失练习结果。

每个关键页面必须包含：

- 本地包缺失；

## 十四、视觉方向

视觉概念：**口袋剧场**。

「我的」保持现有 App 的轻盈、克制和可操作性；进入剧本详情后逐渐增强封面、光影和舞台感；进入播放器后完全沉浸。

“对齐”指交互骨架、组件尺寸、间距和状态反馈与学习计划一致，不是让剧本页复制学习计划的课程视觉：

- 页面容器、顶部图标胶囊、Drawer 圆角、高度、安全区和加载态直接对齐；
- 剧本卡仍使用海报封面、角色与剧情进度，不能变成学习单元卡；
- 广场卡使用作品流布局，不能套用学习计划列表卡；
- 剧本详情和播放器逐级增强沉浸感，离开沉浸页面后恢复现有 App 视觉。

### 14.1 层级变化

```text
剧本首页：学习工具感 70% / 剧场感 30%
剧本商店：学习工具感 40% / 剧场感 60%
剧本详情：学习工具感 25% / 剧场感 75%
VN/跟读：学习工具感 10% / 剧场感 90%
复盘结果：学习工具感 70% / 剧场感 30%
广场：作品展映感 60% / 社交流感 40%
```

### 14.2 关键记忆点

- 剧本封面像“剧目海报”，而不是课程卡；
- 正在练习卡片像“继续演出”；
- 章节使用幕/场的轻量语义，但后台仍保持既有章节模型；
- 视频作品像“演出存档”；
- 广场像学习者作品展映墙，不像泛娱乐短视频平台。

## 十六、推荐实施阶段

### Phase 1：剧本学习闭环

- 底部新增「剧本」；
- 「我的 / 广场」框架，其中广场先做空态或内测入口；
- 我的剧本；
- 剧本商店；
- 剧本详情与章节目录；
- VN / 跟读模式入口；
- 练习记录；
- 复用离线下载与更新。

验收标准：

> 用户能从商店获取剧本，离线进入章节，完成 VN 或跟读，退出后在「最近练习」看到完整记录，并继续下一章。

### Phase 2：视频作品

- VN 视频生成；
- 跟读最佳 take 合成；
- 我的作品；
- 渲染任务状态与通知；
- 私密预览、删除与重新生成。

验收标准：

> 视频生成失败不影响练习记录；用户离开页面后任务继续；生成结果能够准确还原本次练习。

### Phase 3：广场 MVP

- 推荐 Feed；
- VN / 跟读 / 进步筛选；
- 点赞；
- 快捷语；
- 发布/取消发布；
- 举报、隐藏和基础审核；
- 从作品进入同款剧本。

验收标准：

> 广场能够带来剧本详情访问和练习开始，而不只是视频播放时长。

### Phase 4：增长与个性化

- 根据正在学习的剧本推荐作品；
- 完成同一章节的学习者作品；
- 个性化剧本推荐；
- 作品模板与封面；
- 活动型剧本和主题展映；
- 是否需要关注关系，依据真实数据决定。

## 十七、关键产品指标

剧本中心：

- 剧本首页 → 继续练习点击率；
- 商店详情 → 加入/下载转化率；
- 下载完成率；
- 第一章开始率、完成率；
- VN / 跟读模式占比；
- 次日继续剧情率；
- 单剧本完成率。

作品：

- 完成练习 → 发起生成视频比例；
- 视频生成成功率与耗时；
- 生成 → 私密保存比例；
- 生成 → 发布比例；
- 发布后取消比例。

广场：

- Feed 有效观看率；
- 点赞率；
- 快捷语使用率；
- 「练同款」点击率；
- 广场 → 剧本详情 → 开始练习转化率；
- 举报率和隐藏率。

最重要的北极星信号不是广场播放量，而是：

> 有多少用户因为剧本完成了有效开口，并愿意在第二天继续同一部剧本。

## 十八、最终决策

1. 底部导航只新增「剧本」，不新增独立「广场」。
2. 剧本首页内部使用「我的 / 广场」两个 Tab，默认「我的」。
3. 剧本商店和全部练习记录固定为 Header 右上角图标，通过全高 Drawer/Dialog 打开；不作为第三个 Tab，也不默认跳转独立页面。
4. 「我的」首屏优先级固定为：正在练习 → 最近记录 → 我的作品 → 我的剧本 → 商店。
5. 剧本包复用学习包的 zip、离线、资源和下载状态机，但使用独立的剧情进度和产品文案。
6. VN 与跟读每次都产生练习记录；视频是记录的派生作品。
7. 练习记录默认私密，视频生成后默认私密，发布必须主动确认。
8. 广场采用虚拟无限滚动 List，只提供点赞与预设快捷语，不提供评论。
9. 广场内容必须能回到同款剧本与练习链路。
10. 优先完成剧本学习闭环，再做视频，最后开放广场，避免社区能力先于核心体验。

# 离线学习统计

## 账号与状态

沿用现有单用户 SQLite 数据区、退出清空和切号清理。统计表加入同一用户清理列表，
统计 Zustand 在同一边界 reset。清理前暂停新同步、等待当前同步和本地写入完成；
旧计时器和旧统计读取结果通过账号代次失效。公共学习包与资源不受影响。

Zustand 只保存活动计时来源、未提交增量与最多六个统计日期范围的缓存，不再 persist
全部历史时长。SQLite 是持久化事实和统计结果的来源。

## 独立的前后端实现

前端：`sqlite/statistics-schema.ts` 维护 SQLite 触发器；`statistics-projection.ts`
生成远程数据的增量投影语句；repository 按索引日期范围读取。

后端：迁移 `20261114000100_learning_statistics_projections` 中的 PostgreSQL 触发器
在学习事实事务内维护服务端投影，`LearningStatisticsService` 查询投影。
前后端没有互相导入聚合源码，Docker 不复制后端源文件给前端。

不包含旧版格式迁移、旧活跃次数推算或兼容回填。新结构上线前需要应用服务端迁移。

## 表和口径

- `learning_stat_day_questions`：日期 + 题目 ID 唯一；当天重练不增加题数。
- `learning_stat_questions`：题目 ID 唯一；跨日复习不增加累计不同题目数。
- `learning_stat_sources`：日期 + 来源唯一；同来源取累计秒数最大值，独立来源相加。
- `learning_stat_days`：每日题数、有效秒数。
- `learning_stat_totals`：累计题目、学习日、日题数之和、有效秒数；SQLite 同时维护收藏和单词数。

作答事件保留发生时的本地日历日期；当前 guided run 只提供题目集合时使用其指定日期。
对话轮次不混入去重题数，时长仍参与学习活动。月／年作答量是每日题数之和，
不同于月／年范围内的不同题目数。日均题数是每日题数之和除以活跃学习日数。
连续天数从今天开始；今天未学习时从昨天开始，以索引探测连续日期，不读取作答明细。
签到奖励和学习活跃度继续分开，签到日历接口的学习统计采用相同服务端口径。

月查询只读取可见日期范围，年度最多 366 条每日汇总，累计卡片读取单行汇总。
没有单独月表／年表，不依赖普通视图缓存结果。SQL 范围和索引通过查询计划测试。

## 保存与计时

正在学习且 App 可见时，每五秒提交当前变化来源。交互事件只累计内存毫秒，
无操作超过六十秒后不累计；恢复交互不补算空闲区间。同设备只有当前计时器拥有计时权。
计时使用单调时钟，日期归属使用日历时间，跨午夜拆分并保留亚秒余量。
切后台、离开练习主动尝试本地提交；后台停止计时器，回来建立新起点，不补算后台时间。
异常强杀可能损失最后一个尚未提交的保存周期。

作答事实和 outbox 通过原子批次写入，SQLite 触发器同事务更新去重关系和汇总。
计时来源、汇总和对应 outbox 快照也在同一事务内提交。事务失败保留运行时待保存数据。
重试同一事实不重复计数；来源增加五秒时，汇总只增加五秒，不处理历史来源。

## 同步与通知

统一前台调度器每三十秒提供一次上传机会：账号有效、App 可见、网络可用、有待同步项。
无队列时停止周期数据库检查，直到收到新的 outbox 写入通知；有延后重试项时只查索引。
周期任务只上传队列，不拉全量内容清单；前台恢复、登录和手动同步仍走既有同步流程。
网络恢复尝试上传，所有入口共享同一个同步任务。

每轮最多获取一百条到期记录，单次顺序重放轮数受限。普通失败保留且指数退避，
不再按七天删除。清理已确认记录使用索引 DELETE，永久失败沿用丢弃处理。
待同步批次尚未耗尽时不会把退出前同步当作全部成功，避免退出清空未确认数据。
上传只确认对应的不可变修订版本。练习 run 的拉取游标采用更新时间 + ID 稳定分页。

远程题目和来源按批次投影，批次完成只通知一次。统计组件只订阅可见日期范围，
未展示或 App 在后台时不刷新统计；重新进入、恢复前台时读取当前范围。
未完整同步历史时显示不完整状态，读取失败不把已有数据替换成零。

## 日历详情与积分补签

默认打开今天的日视图。月视图单击日期持续高亮，双击（移动端连续轻点两次）进入当天日视图。直接点击“日”默认今天，
左右切换日期，回到月视图保留日期高亮。日视图展示签到状态、完成题数、练习分钟三张卡及小时 chart，
补签入口放在顶部签到状态卡内，日视图与年视图共用背景卡片、顶部日期切换与大图布局，横轴标签单独放在卡片底部，不在日历下方堆叠详情卡。月／年顶部仍为对应范围汇总，月汇总不包含日历补齐的相邻月份日期。
不足一分钟单独显示，历史未恢复完整时不把未知值冒充零。现有统计文案保持原样。

补签固定消耗 **200 积分**，没有回溯天数、月次数或学习记录要求；只允许过去尚未签到的日期。
今天使用正常签到，未来不可补签。补签不发积分、不伪造练习记录，只参与签到连续天数。
个人页“连续打卡”采用签到日期计算的连续段，而学习汇总仍保留真实学习口径。

用户先看到服务端最新余额和费用，再确认扣分。确认请求不进入离线 outbox；离线只能查看缓存。
服务端锁定账号行，在同一事务中查重、校验余额、扣 200 积分、写补签记录及负数积分流水。
同用户同日期的重试返回已完成结果，不重复扣分。其他消费使用条件扣减，数据库约束防止负余额。
签到日历使用 `date`，`createdAt` 只表示操作时间，避免补签被误识别为今日正常签到。
成功回执立即刷新余额、日期标记和连续签到，并更新当前缓存、失效其他日期范围缓存。

新增迁移：`20261114000200_makeup_check_in`。可运行
`python3 apps/backend/scripts/test-makeup-check-in.py` 在临时 PostgreSQL 中验证真实服务与迁移；
该脚本不会读取现有数据库 URL，测试后删除集群。不会自动向现有数据库应用迁移。


## 小时统计

SQLite 与 PostgreSQL 各自维护 `learning_stat_hours` 和 `learning_stat_question_times`，不共用聚合源码。
小时读取按日期索引，最多 24 条；月／年读取不查询小时表。计时在整点和午夜拆分，来源后缀 `:h00`～`:h23`
在原同步协议中携带小时身份。题目按当天首次事件时间归入小时，乱序同步的更早事件可移动所属小时，
重练不重复计题；首次事件小时未知时保持未知，不把重练时间冒充首次时间。
已有每日总量但缺少小时记录时显示缺失或部分明细提示，不分摊、不编造小时数据。
新增迁移：`20261114000300_hourly_learning_statistics`，SQLite schema 版本 17。

小时投影首次初始化时，会从已有练习历史及带小时标识的计时来源补齐可恢复明细，并保存初始化标记，后续启动不扫描历史。日图始终保留，已过去且没有练习记录的小时显示 0，未来小时及尚未载入的数据留空；底部说明明细覆盖范围，不用空明细提示替代整张图。

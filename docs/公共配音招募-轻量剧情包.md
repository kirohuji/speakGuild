# 公共配音招募（轻量剧情包）

更新日期：2026-11-11  
状态：**下个版本**。本文只做产品与边界设计，本迭代不实现。  
定位：管理员发布的**公共活动**，不是用户自发广场招募。

---

## 1. 一句话

管理员给某个轻量剧情包开一场「配音招募」：固定开 **N 组**（例如 10 组）；每组里用户先到先得认领角色、限时录完自己的台词；到点后系统用真人录音 + TTS 补缺合成公共视频；参与者在跟读历史里能看到这份**不可删除**的共同成片。

---

## 2. 为什么和「用户发广场」不一样

| | 旧设想（用户发起） | 现方案（公共活动） |
|---|---|---|
| 谁发布 | 普通用户 | **仅管理员** |
| 作品性质 | 私有 / 可删 | **公共活动成片，不可删** |
| 组数 | 通常 1 组 | 一包可开 **多组**（如 10 组）轮转 |
| 结束条件 | 角色齐了就渲 | **定时到点**统一结算（半天级），角色齐可提前锁组进入下一组招募 |
| 失败责任 | 用户 / 发起人 | **管理员**处理成片失败 |
| 历史记录 | 可删自己的 | **参与者不可删**这条公共记录 |

---

## 3. 核心流程

```
管理员配置并发布活动
  → 打开第 1 组招募席位
  → 用户（已下载该剧情包指定版本）认领角色（先到先得）
  → 认领后进入「限时配音」：录自己角色的全部台词并提交
  → 本组角色席位满员 → 本组招募关闭，开启下一组（直到 N 组）
  → 活动总截止时间到（如发布后约半天）
  → 系统对已提交的各组：真人录音 + 缺行 TTS → 合成视频
  → 成片写入每位参与者的跟读练习历史（公共、不可删）
  → 可选：成片同步出现在广场 / 活动页
```

### 3.1 两阶段（对每一组）

1. **招募 + 配音阶段**  
   认领席位 → 限时录音 → 提交。  
   未在时限内交齐自己角色台词 = **挑战失败**（该用户不计入「成功配音」，缺行仍可用 TTS，但活动侧记失败）。

2. **结算合成阶段**  
   到点后由系统批量渲染；失败由管理员重试 / 修资源，不回滚给用户「重录一轮」。

### 3.2 「组」与「总时限」

- **组（cast group）**：一组完整角色席位。满员后本组不再接受新认领，可开启下一组。  
- **总时限**：整场活动一个截止时刻（例如发布后 12 小时）。到点：  
  - 未满员的组也进入结算（缺角色 / 缺行 → TTS）；  
  - 未提交的认领视为挑战失败；  
  - 不再开新组。  
- **组数上限**：发布时写死（如 10）。到上限后不再开组，只等总时限结算。

---

## 4. 参与规则（已拍板）

1. **管理员发布**；普通用户不能开招募。  
2. **先到先得**认领角色；一人一角（建议默认；若以后要一人多角再开开关）。  
3. **必须已安装该剧情包**，且版本 = 活动锁定的资源版本。  
4. 认领后须在 **认领锁定时长**内完成该角色全部台词并提交；超时 / 未交齐 = 挑战失败。  
5. 成片时 **缺行用 TTS 补上**；挑战失败不等于卡死整组成片。  
6. **无「发起人删记录 / 删号拖垮活动」**路径：活动与成片挂在系统活动实体上，不挂在某个用户私有作品上。  
7. 参与者 **不能删除** 自己跟读历史里的这条公共记录 / 视频。  
8. 成片生成失败 → **管理员**负责重跑；不开放「发布后重录」。  
9. 参与即视为同意成片用于公共展示（报名 / 认领时二次确认文案）。  
10. **不靠「最后一人交卷」触发渲染**；以活动 **定时结算** 为准。组满员只影响「能否开下一组」，不单独立刻出片（除非产品以后加「组满提前结算」开关，默认关闭，避免半场多段视频打扰）。  
11. 弱网：认领锁定 + 录音 **断点续传**（按句 / 按文件资产上传，提交时校验齐套）。

---

## 5. 资源与版本

- 活动发布时 **锁定剧情包 `packageId + revision`**（或等价的 ink / asset 快照标识）。  
- 轻量包一旦进入活动，**原则上不改资源**；若必须修包，应发新 revision 并 **新开活动**，不热更新进行中的招募。  
- 客户端：未下载或 revision 不匹配 → 不能认领，引导下载指定版本。

## 6. 建议数据模型（草案）

名称可按实现调整，语义如下。

### 6.1 `DubbingCampaign`（活动）

- 管理员创建  
- `packageId` / `revision`（锁定）  
- `maxGroups`（如 10）  
- `roleSlots[]`：从剧本解析出的可认领角色列表（排除旁白策略可配置：旁白默认 TTS）  
- `claimTimeoutSec`：认领后须提交的时限  
- `endsAt`：整场截止  
- `status`：`draft | recruiting | settling | completed | failed`  
- `groupCountOpened` / `groupCountSettled`

### 6.2 `DubbingGroup`（第 k 组）

- `campaignId`、`index`（1…N）  
- `status`：`open | locked | settled`  
- 满员 → `locked`（不再认领）；结算后 `settled`  
- `videoAssetId`（组成片，公共）

### 6.3 `DubbingClaim`（席位认领）

- `groupId`、`roleKey`、`userId`  
- `claimedAt`、`deadlineAt`  
- `status`：`claimed | submitted | failed_timeout | failed_incomplete | cancelled_by_admin`  
- 唯一约束：`(groupId, roleKey)` 一人占一席；`(groupId, userId)` 默认一人一角

### 6.4 `DubbingLineTake`（单句录音）

- `claimId`、`frameIndex` / `lineKey`  
- `audioAssetId`、`durationMs`、`uploadedAt`  
- 支持多次覆盖上传直到 `submitted`

### 6.5 跟读历史里的「公共记录」

- 不为每个用户复制一份可删的私有 `ScriptPracticeRecord` 视频所有权。  
- 建议：参与成功结算后，给每位 **submitted** 用户写入一条 **只读引用**：  
  `source: dubbing_campaign`、`campaignId`、`groupId`、`videoAssetId`  
- 删除接口：对该类记录直接拒绝（或 UI 不提供删除）。  
- 真删：仅管理员下架活动 / 合规下架时系统级处理，不是用户「删历史」。

## 7. 交互要点（轻量）

### 7.1 管理员

- 选轻量剧情包 + revision → 配角色席位 → 设组数、认领时限、活动截止 → 发布。  
- 活动页：各组进度、认领列表、挑战失败数、渲染状态。  
- 结算失败：一键重试渲染；必要时替换 TTS / 踢掉异常 claim（谨慎，需审计日志）。

### 7.2 用户

- 广场 / 活动入口看到「进行中的配音招募」。  
- 未下载包：先下载指定版本。  
- 选组（通常只展示当前开放组）→ 选空角色 → 确认同意公共发布 → 进入限时录音 UI（只露自己角色的行）。  
- 进度：已录句数 / 总句数；截止倒计时；提交。  
- 结算后：跟读历史出现「公共配音 · 第 k 组」卡片，可播放，无删除。

### 7.3 弱网与锁定

- 认领成功即占席，倒计时开始。  
- 录音按句上传资产（已有 file-asset 能力可复用），本地可缓存 pending。  
- 提交 = 服务端校验：该角色所需 lineKey 是否都有 asset；缺句可提示补录，到 `deadlineAt` 仍缺 → `failed_incomplete`，席位不再释放给他人（避免临截止抢位）；成片该角缺行走 TTS。

---

## 8. 定时与并发

- **唯一结算触发**：`endsAt` 到点（BullMQ delayed job / cron 扫到期活动）。  
- 组满员：只 `lock` 本组并 `open` 下一组（若未达 `maxGroups` 且未到 `endsAt`）。  
- 多人同时交最后一句：提交接口幂等；结算 job 幂等（同一 `groupId` 只入队一次渲染）。  
- 不在「最后一人提交」时立刻全场出片，避免与定时策略打架；若产品要「组满立即出片」，作为可选开关，默认关。

---

## 9. 边界清单（实现时必测）

| # | 边界 | 处理 |
|---|---|---|
| 1 | 未下载 / revision 不符 | 禁止认领 |
| 2 | 活动进行中改包 | 禁止；新 revision 新活动 |
| 3 | 同角色并发认领 | DB 唯一约束，先到先得 |
| 4 | 认领后未录完 | 挑战失败 + TTS 补缺 |
| 5 | 用户删号 | 成片与活动仍在；署名可显示「已注销用户」 |
| 6 | 用户想删历史 | 不允许 |
| 7 | 渲染失败 | 活动 `failed` 或组成片失败标记；管理员重试 |
| 8 | 想重录 | 不支持 |
| 9 | 到点仍有 open 组 | 照常结算，空席 / 未提交 → TTS |
| 10 | 已开满 N 组但未到点 | 停止新组，等 `endsAt` 结算 |
| 11 | 弱网重复提交 | 上传与 submit 幂等 |
| 12 | 旁白 / 系统行 | 默认不进席位，直接 TTS |
| 13 | 合规下架 | 管理员下架活动与视频；用户历史显示不可用 |

---

## 10. 刻意不做（本功能 v1）

- 用户自发开招募  
- 参与者删除公共历史 / 视频  
- 发布后重录、换人补录（除非管理员工具）  
- 用「最后一人交卷」作为唯一出片信号  
- 热更新进行中活动的剧情包资源  

---

## 11. 和下个版本的衔接

实现前建议再钉死的两个产品开关（可默认如下）：

1. **组满是否立刻渲染该组**？默认 **否**，统一 `endsAt` 结算。  
2. **挑战失败的用户**是否仍出现在成片署名里？默认 **仅 submitted 成功者署名**；失败者不署名但 TTS 仍可能用到其已上传的部分句子（或全部丢弃改 TTS——需二选一，建议：**已上传句子仍用，未上传 TTS**，署名仅 submitted）。

确认后可拆任务：

- Prisma：Campaign / Group / Claim / LineTake + 历史只读引用  
- Admin：发布与监控  
- App：活动页、认领、限时录音、断点续传、只读历史卡  
- Worker：到点结算 + 复用现有 script-video 渲染管线（按角色合并 recording map）

---

## 12. 与现有跟读视频的关系

- 现有「个人跟读 → 生成私有视频 → 可删 / 可重生成」继续独立。  
- 公共配音是 **另一条产品线**：管理员活动 + 不可删公共成片。  
- 渲染管线可复用（帧时间轴、录音注入、图片压缩、Remotion），差别在 **录音来源按角色合并自多用户**，以及 **产出资产的所有权 / 可见性模型**。

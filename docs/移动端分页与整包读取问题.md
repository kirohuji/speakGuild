# 移动端分页与整包读取问题

排查日期：2026-11-06。范围是用户端移动页面，不含管理后台。

结论：前端没有任何一处用 SQLite 的 `LIMIT` / `OFFSET` 按页取数据。翻页只有两种做法：向后端请求一页，或者先把数据全部放进内存再 `slice`。学习包详情、话题准备页感到慢，是因为打开列表之前先解析了整行大 JSON。

## 真正按页向后端要数据

| 页面 | 位置 | 做法 |
|---|---|---|
| 学习商店 | `apps/frontend/src/features/learning/components/shop-view.tsx` 滚到底；`apps/frontend/src/stores/learning.store.ts` 的 `fetchShop` / `loadMoreShop` | `learningApi.getUnits({ page, pageSize: 20 })`，下一页再请求 |
| 通知列表 | `apps/frontend/src/features/notification/components/notification-bell.tsx`；`apps/frontend/src/features/notification/store.ts` | `getUserNotifications({ page, pageSize })`，滚到底再要一页 |
| 剧本中心第一屏 | `apps/frontend/src/features/scripts/pages/script-center-page.tsx` 约第 248 行 | 只向后端要 `page: 1, pageSize: 30` |

这三处外面的 Virtuoso 只是少画 DOM。数据本身已经按页拿过。

## 伪分页

数据先全部进入内存，页码只对数组做 `slice`。

| 页面 | 位置 | 切的是什么 |
|---|---|---|
| 学习包详情 | `apps/frontend/src/features/learning/pages/learning-unit-page.tsx` 的 `PrepPager` | `unit.vocabularies` / `chunks` / `sentencePatterns` / `trainingTopics`，每页 8 条 |
| 练习话题准备页 | `apps/frontend/src/features/practice/pages/practice-session-page.tsx` 的 `PrepPager` | 同上，来自整份话题详情 |
| 写作 / 阅读 / 听力的话题列表 | `apps/frontend/src/features/learning/components/content-mode-experience.tsx` 的 `PrepPager` | 已经挂在 `unit.trainingTopics` 上的话题 |
| 今日任务话题 | `apps/frontend/src/features/learning/pages/today-task-page.tsx` 约第 884 行 | `plan.topicStats.slice` |
| 今日记录抽屉 | `apps/frontend/src/features/learning/components/today-records-drawer.tsx` 第 39 行 | 已传入的 `records.slice` |
| 学习计划里的练习记录、知识点记录 | `apps/frontend/src/features/learning/pages/learning-plan-page.tsx` 的 `ConfigDataTable` | 本地记录全部取出后再切页 |
| 个人页练习记录 | `apps/frontend/src/features/profile/components/records-tab.tsx`，调用 `apps/frontend/src/lib/offline/practice.repository.ts` 的 `listPracticeRecords` | `localDb.list('practice_records')` 全表，再 `slice` |
| 剧本中心章节、发布记录 | `apps/frontend/src/features/scripts/pages/script-center-page.tsx` 约第 988、1926、2315 行 | 已在内存里的 `filtered` / `topics` 再切页 |
| 学习库单词 / 句块 / 句型 | `apps/frontend/src/features/expression/pages/expression-library-page.tsx`；`apps/frontend/src/lib/offline/learning-notebook.repository.ts` 第 119 行 `listCachedExpressionItems` | `expression_entries` 和 `learning_notebook_items` 两张表整表 `list`。Virtuoso 只负责少画节点 |

学习库不是数据库分页。页面上的 `PAGE_SIZE = 30` 只写在结果对象里，列表用的是这次读出来的全部条目。它还能接受，是因为一个单词一行，单行很小。

学习包详情的 `PrepPager` 也不是数据库分页。`paginateItems` 是对已经解析完的数组做 `slice`。翻页很快，是因为整包已经在内存里。慢的是第一页出现之前的那一次解析。

## 整包 JSON 在哪里读

已下载学习包在 SQLite 表 `downloaded_unit_details` 里有一整行，id 是学习包 id。这一行叠着全部单词、句块、句型，以及每个话题的教学文档和练习流水线。读取后 `sqlite-json-store.ts` 的 `hydrateRow` 会 `JSON.parse`。

统一入口：

- `apps/frontend/src/lib/offline/learning.repository.ts` 第 365 行 `getCachedUnitDetail`：`localDb.get('downloaded_unit_details', unitId)`，再进 `aggregateUnitContent`。没有 `__offlineAggregatedView` 时，还会按话题再读 `topic:{id}`。
- 同文件第 233 行 `mergeLocalPracticeProgress`：每个已安装包都读这一整行，用来重算词数、句块数和进度。

打开页面就会走到这些入口的位置：

| 场景 | 位置 |
|---|---|
| 学习包详情 | `learning-unit-page.tsx` 第 101 行 `fetchUnitDetail` |
| 写作话题 | `writing-session-page.tsx` 第 69 行 |
| 阅读话题 | `reading-session-page.tsx` 第 39 行 |
| 听力话题 | `listening-session-page.tsx` 第 41 行 |
| 阅读器 | `learning-reader-page.tsx` 第 90 行 |
| 回到学习计划 | `learning-plan-page.tsx` 进入时 `fetchMyLearning`，经 `getMyUnits` 走到 `mergeLocalPracticeProgress`，每个已下载包各读一整行 |
| 今日任务建计划 | `daily-practice.repository.ts` 第 560–569 行 `loadCandidateUnits`，每个已加入且已安装的包各读一整行 |
| 设为当前练习包 | `daily-practice.repository.ts` 第 809 行 `setActivePracticePackId` |
| 回看写作 / 阅读记录 | `topic-session-readonly-review-drawer.tsx` 第 54 行 `getUnitDetail` |

单条话题的大 JSON 是同一张表里 `topic:{话题 id}` 那一行。入口是 `apps/frontend/src/lib/offline/practice.repository.ts` 第 45 行 `getCachedTopicDetail`。旧数据缺场景信息时，第 59 行还会再读整包那一行。

调用方：

| 场景 | 位置 |
|---|---|
| 练习话题准备页 | `practice-session-page.tsx` 经 `practice.store.ts` 的 `fetchTopicDetail` |
| 今日任务判断教学文档 | `today-task-page.tsx` 第 854、939 行 |
| 学习计划回看一条练习 | `learning-plan-page.tsx` 第 586 行 |

另外，`apps/frontend/src/lib/offline/learning-content.repository.ts` 的 `getChunk`、`searchChunks` 在 `offline_chunks` 没有命中时，会 `localDb.list('downloaded_unit_details')`，把所有包的整行都读出来再查找。

下载、更新、卸载时写入或删除这些行的代码在 `learning-pack.service.ts`（`persistUnitContent` 约第 157–172 行）。那是安装路径，不是打开页面的路径。

## 和体感的对应关系

- 冷启动第一次打开学习包详情或练习话题：页面要等上面的整行解析完才撤掉骨架屏。列表上的 8 条分页发生在解析之后。
- 同一次打开里再进同一个学习包：详情已经在内存 store 里，`learning-unit-page.tsx` 会跳过骨架屏。写作、阅读、听力同样复用这份内存数据。练习准备页没有复用，仍会再读 `topic:{id}`。
- 学习计划切走再回来：页被卸载后重新进入，`fetchMyLearning` 对每个已下载包再解析整行。封面用了 `loading="lazy"`（`my-learning-view.tsx` 约第 292 行），节点拆掉后会先闪渐变底再出图。

# 离线签到

正常签到统一先写本地。`check-in.repository.ts` 在同一个本地事务中保存签到记录和
`check_in` outbox 操作，成功落盘后首页显示签到成功。在线时立即尝试现有 syncPending，
离线时保留队列，恢复网络后重试。签到记录使用账号和日期去重，不新增 SQLite 表。

首页和日历从同一份记录投影签到状态。现有签到日历缓存继续使用，未上传记录覆盖
远端旧状态；未缓存的历史日期保持未知。跨日、回到前台、恢复网络时刷新首页状态。
服务端签到确认后更新可用积分，离线签到不提前增加可消费积分。

服务端继续使用 `/points/check-in`，额外接受 date、occurredAt、timeZone、
clientMutationId 和 ownerId。ownerId 仅作为账号一致性断言，实际用户仍取自登录会话。
无 body 的旧调用仍表示当天签到。离线签到日期必须与发生时间、时区一致，不能是未来日期。

沿用用户行锁和 userId/date 唯一约束，在同一事务中创建签到、增加积分和写积分流水。
同一天重复请求返回已有结果，不重复奖励。多天积压按日期处理；连续奖励按服务端处理时
已确认记录计算，不追溯重算历史奖励。重复日期已有付费补签时直接确认现有记录，不额外发积分。

付费补签仍需联网，成功后保存统一签到状态。补签按钮采用 secondary 背景，不使用描边；
确认弹窗使用现有应用表面背景、窄宽度、圆角和按钮布局。

账号切换暂停写入并等待当前本地事务完成，再执行既有账号清理；新 KV 前缀纳入清理与归档。
进行中的旧账号请求不能覆盖新账号。清除本地用户数据仍会清除未上传签到，沿用现有登出提醒。

部署顺序：先部署支持离线日期与幂等响应的后端，再更新客户端。
验证按要求仅运行前后端 typecheck，不运行 build、浏览器或运行时测试。

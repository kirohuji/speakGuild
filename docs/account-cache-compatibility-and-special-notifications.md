# 旧缓存归属确认与首页特殊广播

## 单用户缓存架构

继续使用一套活动 SQLite 数据空间，切换用户时清理用户数据，保留学习包、词典和模型等公共资源。新增 SQLite `kv` 标记 `offline-account:owner`，原有 localStorage 归属标记作为旧版迁移入口。SQLite 标记存在时优先使用它，避免单独丢失 localStorage 标记造成误认领。

进入业务页面及启动同步前先确认缓存归属。冷启动不再直接公开缓存 session；网络会话检查超时可回退缓存会话，但仍必须完成本地归属检查，不能通过加载超时跳过该检查。

## 旧版兼容

- 已有归属标记且属于当前账号：继续使用本地数据。
- 没有归属标记且没有用户数据：初始化为空的当前账号空间。
- 没有归属标记但存在旧数据：检查旧缓存会话、待同步操作的 `ownerId`、`user_profile:{userId}`。存在矛盾证据时不认领；能确认同账号时保留原数据、原关联和待同步记录。
- 归属仍无法确认：先备份隔离，再初始化当前账号；不会将未知数据展示或上传到新账号。首次隔离完成会显示提示。

隔离备份存放在 `kv` 的 `offline-account-archive:{archiveId}`，格式为 `sqlite-rows-v1`，保留用户表的全部原始 SQLite 行、用户范围的 kv 和旧版 localStorage 进度。原生录音目录移动到 `Directory.Data/offline-account-archives/{archiveId}/user-recordings`。录音移动失败或备份写入失败时不会清理活动数据。

备份键不属于普通登出清理范围，不会参与同步。归属不明的备份不自动合并；后续恢复必须先核实原账号。备份中 `tables` 保存原始列（包含 `id`、索引列和 JSON `data`），恢复时不能仅导入 `data` 字段；录音引用也需要对应备份路径。当前没有新增自动恢复或后台上传功能。

## 清理中断

清理前先落盘 `offline-account:transition`，清理成功后事务提交新归属并移除过渡标记。清理失败时错误向上抛出，保留旧归属和过渡标记、暂停同步，不公开新账号业务会话。重启或重新登录会重试清理；即使再次登录旧账号，也不会把已经部分清理的数据当作完整数据直接放行。

归属未知的备份先于清理完成，清理中途失败后的重试复用同一备份，不以已经被清理了一部分的数据覆盖原备份。显式登出同样使用过渡标记。后台管理路由原有保留 App 数据的行为保持不变。

## 首页特殊广播

`GET /notifications/special` 先按用户可见性选出最新一条特殊通知，再判断该用户是否已读。已读则返回空列表，不回退到历史未读广播。使用创建时间与 ID 确定稳定顺序；定向消息仍按接收用户限制。

此逻辑只影响首页自动展示候选；不把旧通知批量标已读，不改变通知列表和未读统计。新发布的特殊通知仍可以成为新的弹出候选。

## 验证

覆盖旧缓存同账号迁移、归属证据冲突、未知数据及录音隔离、清理失败阻断、重启重试、失败登出、录音移动失败、首页最新通知已读后不回退，以及账号初始化完成前不公开业务会话。未运行 build、浏览器或 iOS 真机验证；无需数据库 schema 迁移。

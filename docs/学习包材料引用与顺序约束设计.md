## 1. 三个字段是干嘛的（现状说明）

| 字段 | 字段名（DB） | 取值 | 作用 | 谁来用 |
|---|---|---|---|---|
| **所属分类** | `Scene.categoryId` → `SceneCategory` | 管理员自由创建（如"留学生活"），带 icon 与 sortOrder | 内容组织维度：把学习包按主题/领域归档，前端列表、筛选、分类展示 | 内容归档、列表分组 |
| **学习包类型** | `Scene.packageType` → `LearningPackageType` | `daily` 日常 / `exam` 考试专项 / `course` 付费课程 / `foundation` 零基础 | 商业化与定位维度：决定付费/免费策略、学习路径定位（如 exam 包话题默认雅思题型） | 定价、学习路径、话题默认配置 |
| **内容体验** | `Scene.contentMode` → `ContentMode` | `practice` 知识点练习 / `writing` 写作 / `reading` 阅读 / `listening` 听力 / `novel` 小说(EPUB) / `story` 剧情 | 交互与题型维度：决定话题里出现什么题型 Tab、用户端主交互（播放器/写作台/听力会话/剧本） | 用户端体验、话题编辑器结构 |

三者是**互相独立的三个维度**，一个学习包同时属于：某个分类 + 某种类型 + 某种体验（例如"留学生活 / 日常 / 听力"）。**它们都不是顺序约束**——顺序约束由新增的 `Scene.groupId` + `Scene.sortOrder`（组内学习顺序，从 0 开始）承担（见 §3.1）。

## 2. 需求背景

目前系统的材料（单词 / 句块 / 句型）是**全局共享**的：

- 包级绑定：`SceneVocabulary`、`SceneChunk`、`SceneSentencePattern`
- 话题级绑定：`TrainingTopicVocab`、`TrainingTopicChunk`、`TrainingTopicSentencePattern`（话题内有 `@@unique` 防重复，但**跨话题、跨包没有去重**）

结果是：同一个词可以在包 A 和包 B 里都作为"新学知识点"，AI 生成练习时也可能随机引用未来包的知识点，导致：

1. 学习者按顺序学 1-10 号包时，后面的包重复前面已学过的单词/句块/句型（浪费、挫败感）；
2. AI 生成的练习可能提前出现后续包的知识点（超纲/剧透）；
3. 练习难度与包的目标难度（`requiredOutputLevel`）脱节；
4. "关联词汇"只能靠人工在全局词汇库翻找，无法保证与已绑句型/句块搭配、且不与其他包冲突。

**目标**：建立一套"材料引用约束"，让学习包组内的内容不重复、不超纲、难度匹配，AI 生成的练习和推荐词汇都受约束控制。

## 3. 核心概念

### 3.1 两层学习顺序（组 → 包 → 话题）

顺序约束分**两层**，都必须在库里有显式字段，约束引擎与 AI 生成直接读取：

```
学习包组 PackageGroup
 └─ 学习包 Scene（组内顺序 Scene.sortOrder，从 0 开始）
     └─ 话题 TrainingTopic（包内顺序 TrainingTopic.sortOrder，从 0 开始）
```

1. **层 1 · 组内包与包之间**：1-10 号学习包是一组，组内每包有一个**组内顺序号**（从 0 开始）；后面的包不能把前面包已认领的材料当作新学知识点。
2. **层 2 · 包内话题之间**：包内话题同样有序，后话题不能重复前话题认领的材料。

> ⚠️ 现状：包级顺序藏在 `PackageGroupItem`（内容体验面板「系列设置」，可不加入系列），话题级 `TrainingTopic.sortOrder` 已存在但**从未参与任何约束校验**。
> 本次需求：**新增两个字段 `Scene.groupId` + `Scene.sortOrder`**（见 §4.1①），把"组内顺序"升级为约束引擎和 AI 生成的第一事实源。

- 顺序是引用约束的**基础坐标**：约束只在**同一个组内**（`groupId` 相同）生效；不同组之间材料可重复认领。

### 3.2 材料认领（Claim）与引用（Reference）

- **认领 = 把某个材料（词/句块/句型）作为"新学知识点"绑定到某包或某话题**。认领来源：
  - 包级：`SceneVocabulary` / `SceneChunk` / `SceneSentencePattern`
  - 话题级：`TrainingTopicVocab` / `TrainingTopicChunk` / `TrainingTopicSentencePattern`
- **引用 = 材料出现在包内任意内容的记录**（包括认领、也包括练习题中实际用到），用于统计与覆盖检查（现已有 `materialUsage`，见 `warmup-pipeline-tab.tsx` 的 `buildWarmupMaterialUsage`）。

**核心规则**：后包不得**认领**前包已认领的材料（不重复学习）；但前序材料允许出现在后包的例句/练习题中作为**复习复用**（role=review）。

## 4. 引用表设计

### 4.1 数据模型（新增两个顺序字段 + 引用表）

**① 顺序字段（新增，约束事实源）** — 学习包上直接加"组 + 组内顺序"两个字段：

```prisma
model Scene {
  // ...现有字段...
  groupId   String?       // 新增：所属学习包组（null = 未入组，无顺序约束）
  group     PackageGroup? // 新增：多对一关系
  sortOrder Int    @default(0) // 新增：组内学习顺序，从 0 开始
}
```

- 入组/排序时，`Scene.groupId`、`Scene.sortOrder` 与 `PackageGroupItem` 在同一事务内同步维护（`PackageGroupItem` 继续保留 `volumeLabel`、`requiredPrevious`；后续可把这两个字段也并入 `Scene`，删掉中间表）。
- 一次性回填：把现有 `PackageGroupItem.sortOrder` 迁移到 `Scene.sortOrder`。
- 话题级已有 `TrainingTopic.sortOrder`，**无需新增**，但要纳入校验。

**② 引用表（新增 Prisma 模型）**：

```prisma
enum MaterialType {
  vocab
  chunk
  pattern
}

enum MaterialClaimRole {
  learn    // 新学目标（认领）
  review   // 复习复用（前序包/前序话题的材料，出现在本包练习题中）
}

model SceneMaterialReference {
  id           String          @id @default(cuid())
  sceneId      String
  scene        Scene           @relation(fields: [sceneId], references: [id], onDelete: Cascade)
  materialType MaterialType
  materialId   String          // 指向 vocabulary.id / chunk.id / sentence_pattern.id（不建物理外键，材料库全局共享）
  topicId      String?         // 认领来源话题；null = 包级认领
  role         MaterialClaimRole @default(learn)
  createdAt    DateTime        @default(now())
  updatedAt    DateTime        @updatedAt

  @@unique([sceneId, materialType, materialId])
  @@index([materialType, materialId])
  @@index([sceneId, topicId])
  @@map("scene_material_reference")
}
```

> 为什么单独建表而不是直接用现有关联表当引用表：需要记录 **role（learn/review）**、**来源（包级/话题级）**，并支持"仅练习题引用但不认领"的场景；且后续组内重排、批量校验都只查这一张表，不触碰现有业务表。现有关联表**继续作为认领的写入源**，引用表由写入逻辑同步维护（同一事务内）。

### 4.2 同步时机（引用表的写入）

| 操作 | 动作 |
|---|---|
| 保存话题（增删 `chunkIds/vocabIds/patternIds`） | 事务内同步 upsert/删除该话题的 learn 记录 |
| 保存包级知识（`updateKnowledge`，novel 等无话题场景） | 同步包级 learn 记录 |
| 删除话题 / 解绑材料 | 删除对应记录，释放认领 |
| 学习包发布打包 | 只读引用表，写入包清单快照（离线包内自带引用信息，供客户端校验） |
| AI 生成练习时实际用到的前序材料 | 追加 role=review 记录（由生成结果回写，可选） |

### 4.3 组上下文计算（AI 约束的输入）

给定 `sceneId`，先读 `Scene.groupId` + `Scene.sortOrder`（未入组则无组约束，只做包内话题约束）：

- `sortOrder`：本包在组内的顺序（层 1）
- `earlierClaims`：同组内 `sortOrder < 本包` 的所有包的认领材料（learn + review 都算，`GROUP BY materialType, materialId`）
- `laterClaims`：同组内 `sortOrder > 本包` 的认领材料

## 5. 顺序约束规则（校验逻辑）

### 规则 A：组内跨包不重复认领（层 1）

> 同一 `groupId` 下，顺序为 i 的包（`Scene.sortOrder`），新增认领材料时，禁止命中 `earlierClaims`（同组 `sortOrder < i` 的包认领集合）。

- **校验时机**：话题保存、包级知识保存时（后端 `MaterialConstraintService.assertCanClaim`，先读 `Scene.groupId`/`Scene.sortOrder` 确定组上下文）。
- **冲突处理**：默认**阻止保存**并提示「该材料已在《xxx》包（顺序 n）作为知识点使用」；提供「改为 review 复用」的选项（写入 role=review，不占新学名额）。
- 已认领材料可以出现在**例句、练习题**中（不视为违规）。

### 规则 B：包内话题不重复认领（层 2）

> 同一包内（`sceneId` 相同），话题按 `TrainingTopic.sortOrder` 升序，后话题不得认领前话题已认领的材料。

- 实现上复用同一套校验，把"前序集合"换成 `本包内 sortOrder < 当前话题` 的话题认领并集。
- 现状：话题内已有唯一约束；规则 B 补上话题之间这一层。

### 规则 C：组内重排校验

> 把包从顺序 3 移到顺序 1 时，可能突然与前序包冲突。

- 重排保存时（`assignSceneGroup` 的排序逻辑处）做一次全组扫描，冲突的包以警告列表展示，管理员确认后仍可保存（**不强制阻止重排**，但 UI 必须明确展示冲突，防止无感知违规）。

### 规则 D：组是约束边界

- 不同组之间、未入组的包之间，材料可以重复认领（互不约束）。
- 后序包允许提前认领（预配置材料库），只是生成内容时对其不可见（见 §6）。

## 6. AI 生成约束（编辑话题 → 知识点练习 →「全部 AI 生成」）

### 6.1 现状

- 前端 `warmup-pipeline-tab.tsx` 调 `POST /practice-ai/generate-warmup-pipeline`，材料只传**当前话题绑定**的词汇/句块/句型，prompt 已有 `core / ext / carry` 分级（carry = 本包前序话题复用词）。
- 后端 `english-practice-ai.service.ts#generateWarmupPipeline` 按材料组装 prompt，无任何组/包上下文。
- 教学文档生成接口 `training-topics/:id/generate-teaching` 目前是**空实现**（`content-admin.controller.ts` L2285-2289，需补全）。

### 6.2 需求

**约束上下文 = 话题所在的"这一套学习包"（整组）**，不是只看当前包：

```
当前话题（属于组 G 中顺序为 i 的包）
 ├─ 允许（learn）  ：当前包认领 + 当前话题绑定
 ├─ 允许（review） ：组 G 内顺序 < i 的包认领 + 本包前序话题认领
 └─ 禁止（excluded）：组 G 内顺序 > i 的包认领（防超纲/剧透）
```

1. **禁止未来知识点**：生成的练习题、例句、提示中，不得出现**组内后序包**（`Scene.sortOrder > i`）已认领的材料（防超纲/剧透）。
2. **允许前序复习**：**组内前序包**（`Scene.sortOrder < i`）与本包前序话题的材料可作为 carry/review 词出现在题目中（复用现有 carry 机制）。
3. **难度对齐**：以学习包 `requiredOutputLevel`（兜底）+ 话题 `difficulty` 为准，prompt 中明确"目标难度为 X，核心词控制在 L1-Ln"。
4. **教学文档生成同样受约束**：补全 `generateTopicTeachingMarkdown`，注入与练习生成相同的约束上下文。

### 6.3 实现方案

- 后端 `GenerateWarmupPipelineDto` 增加可选字段：
  ```ts
  constraints?: {
    sceneId?: string;              // 后端据此查引用表 + Scene.groupId/sortOrder（优先，防前端伪造）
    excludedMaterialIds?: string[]; // 兜底：显式传入的禁止集合
    reviewMaterialIds?: string[];   // 兜底：显式传入的复习集合
    difficulty?: string;            // 目标难度
  }
  ```
- 后端强制（不只依赖前端）：拿到 `sceneId` 后 → 读 `Scene.groupId`、`Scene.sortOrder` → 取同组全部 `SceneMaterialReference` → 服务端计算**整组上下文**：`excluded`（组内后序包认领）/ `review`（组内前序包 + 本包前序话题认领），**过滤后**再进 prompt；`excluded` 同时从 `previousPipeline` 里清洗掉。
- prompt 模板（`warmup-pipeline.prompt.ts`）增加两节：
  ```
  ## ══ Forbidden Materials (MUST NOT appear anywhere) ══
  （后序包知识点，逐条列出，禁止出现在题目/例句/提示中）
  ## ══ Review Materials (carry, nice-to-have) ══
  （前序包知识点，仅允许作为复习复现）
  ```

## 7. 关联词汇「根据句型和句块」推荐

### 7.1 需求

练习配置 →「关联词汇」Tab 增加按钮**「根据句型和句块推荐」**：从全局词汇库中找出与当前已绑**句型 + 句块**搭配合理、适合本包练习的单词，结合**教学文档**与**引用表约束**给出推荐。

### 7.2 输入 / 输出

- 输入：`patternIds`（已绑句型）、`chunkIds`（已绑句块）、话题难度、`teachingMarkdown`、当前 `sceneId`
- 输出：Top N（默认 8）推荐词，每项含：
  - 单词、释义、难度、词性
  - **推荐理由**（与哪个句型/句块搭配，AI 一句话说明）
  - 状态标记：`可认领` / `已被前序包认领（仅可复习）` / `已被后序包认领（不可用）`

### 7.3 实现方案（两段式）

1. **规则预筛（服务端，快、可解释）**：
   - 引用表过滤：排除后序包认领；前序包认领的词降级为 review 候选（默认不推，除非词库稀缺）；
   - 难度过滤：词汇 `difficulty` 在目标难度 ±1 内；
   - 搭配初筛：根据句型 `slots`（如 `[subject][verb]...`）与句块词性、词汇 `collocations`/`partOfSpeech` 做启发式匹配（如句型需要动词位，优先及物动词/短语动词）。
2. **AI 排序与理由（DeepSeek）**：把预筛结果 + 句型/句块/教学文档/难度塞进 prompt，输出排序 + 每条推荐理由，保证"不是乱生成"。

### 7.4 新接口

```
POST /admin/content/training-topics/:id/suggest-vocabs
Body: { patternIds: string[], chunkIds: string[], difficulty: string, teachingMarkdown?: string }
返回: { items: [{ vocabularyId, word, meaning, difficulty, reason, claimStatus }] }
```

### 7.5 UI

- 「关联词汇」Tab 头部放按钮 + 说明文案（"根据已绑句型与句块推荐搭配词汇"）；
- 结果以卡片列表展示，每项可勾选 →「加入关联」写入 `vocabIds`；
- 已推荐但被约束拒绝的词置灰并显示原因。

## 9. 边界情况与决策点

| 场景 | 处理 |
|---|---|
| 包移出组 / 换组 / 未入组 | `Scene.groupId` 置空/更换，`sortOrder` 重排；引用记录保留，约束范围随组变化，换组后与新组内包重新校验 |
| 组内重排产生冲突 | 允许保存但**必须**展示冲突列表（不静默） |
| 删除话题 / 解绑材料 | 释放认领（引用表级联或事务删除） |
| 后序包尚未发布 | 可提前认领；生成约束照常生效（不泄露） |
| 同词在不同组 | 允许（组是约束边界） |
| 前序材料作复习用 | 记录 `role=review`，不计入"新学"查重 |
| 词汇库词太少，前序包几乎认领完 | 推荐接口允许兜底：把前序认领词作为 review 候选并明确标注 |
| 离线学习包 | 发布打包时把引用表快照打进包清单，客户端可展示"本包新学 X / 复习 Y" |

**待决策**：
1. 冲突时默认"阻止保存"还是"警告可保存"？（建议：包内话题冲突阻止，组内重排冲突警告）
2. 引用表是否需要记录"练习题实际引用"（role=review 由 AI 结果回写），还是仅人工绑定？（建议 M1 先只做认领，review 回写放 M2）
3. 推荐词汇的 AI 排序是否可接受额外 LLM 调用成本？

# 剧本中心 · 叙事剧情包（Narrative Story Pack）

更新日期：2026-11-12  
状态：**下个版本**。本文只做产品与内容管线设计，本迭代不实现。  

> **已拍板（2026-11-12）**  
> - 漫语町更重视**剧情与叙事**；本包放在**剧本 Tab**，不进学习计划。  
> - **不做「博客包」**，也不把广场扩成英语新闻流（运营成本过大）。  
> - 与现有**轻量剧情包**（`packageType=story`）不同：轻量包为练习开口；本包为叙事沉浸，跟读是体验的一部分，不是练习题工厂。

---

## 1. 一句话

用可合法使用的英语叙事文本，做成有画面、有配音的短剧情包，放在**剧本中心**；用户可看剧、进跟读剧场，并把**自己的跟读片段**发到广场。生产管线：原文 → Hume 配音 → NovelAI 画面 → ffmpeg / Remotion 成片。

---

## 2. 产品定位：两类「剧情」不要混

| | **轻量剧情包**（已有 `story`） | **叙事剧情包**（本方案） |
|---|---|---|
| 核心目的 | **为了练习**：短对白、可跟读、可配音成片 | **为了剧情**：沉浸叙事、角色与气氛 |
| 入口 | 剧本中心 | 剧本中心（同一 Tab，不同分类） |
| 主玩法 | VN / Ink 互动 + 跟读剧场 + 整段作品 | **看叙事短片** + 可选跟读剧场 + **片段发布** |
| 分支 / 选择 | 有（练习意图） | MVP **无分支**，线性叙事 |
| 学习计划 | 不出现 | **不出现** |
| 占「同时 3 包」 | 否 | 否 |
| 完成感 | 练完一集 / 生成作品 | 看完一集故事；跟读与发布为加分体验 |

剧本 Tab 内建议分类展示，例如：

```text
剧本中心
├─ 口语剧本     ← 轻量剧情 story（练习向）
├─ 互动小说     ← nqtr
└─ 叙事短剧     ← 本方案（下版本）
```

底部 Tab 名仍可叫「剧本」；若日后品类再增，再考虑改成「剧场」。本方案**不强制改名**。

## 3. 用户体验（MVP）

### 3.1 主路径

```text
剧本商店安装叙事短剧包
  → 选集 / 看官方成片（沉浸，可关字幕）
  → 可选：进入跟读剧场（复用现有 repeat theatre 能力）
  → 可选：把自己跟读的若干句合成「片段」→ 发布到广场
  → 进度：看完 / 跟读过即可记一集完成（不做题海）
```

### 3.2 跟读与发布（和轻量包的差别）

| | 轻量剧情包 | 叙事剧情包 |
|---|---|---|
| 跟读 | 核心练习环 | **可选增强**：跟角色说同一句话 |
| 发布到广场 | 常为整集 / 整段配音作品 | **鼓励片段**：高光句、名场面、个人朗读 clip |
| 渲染 | 已有 script-video 整段作品流 | 复用同一管线；产物 kind 可标 `narrative_clip`（名称待定） |

原则：叙事包**不以刷题、占今日任务为目标**；跟读是「入戏」，不是「交作业」。

### 3.3 明确不做（控制运营成本）

- 博客包 / 对话资讯包  
- 广场英语新闻 / 资讯流  
- 学习计划混入叙事包进度  
- 与听力包、阅读包同构的理解题工厂（可留极少量可选「剧情回顾」题，默认关闭）

## 4. 内容生产管线

```text
原文筛选（版权 OK）
  → 改编为短叙事分镜（旁白 + 角色对白，控制集长）
  → 分镜脚本（speaker / text / emotion / visual prompt）
  → Hume AI 逐句 / 逐角色 TTS
  → NovelAI 背景 + 立绘（固定角色卡）
  → 组装 timeline frames（对齐现有 ScriptVideo 帧结构）
  → ffmpeg 批量出片（默认）或 Remotion 精品
  → 打剧本侧安装包（视频 + 音频 + 图 + 跟读时间轴）
  → 剧本商店上架
```

### 4.1 原文来源

1. 公有领域（确认 PD）  
2. 明确商用 CC  
3. **漫语町原创叙事**（最贴品牌，优先试点）  
4. 禁止未授权现代作品搬运  

改编偏**叙事完整感**：每集有起承转合；语言点服务故事，不为练某个语法硬塞句子。

### 4.2 Hume / NovelAI / 渲染

与初版设想相同，要点不变：

- Hume：角色 voice 固定；旁白可跟读策略可配置（默认旁白可听、角色句可录）。  
- NovelAI：角色卡 + 场景模板；确认商用条款。  
- **ffmpeg 默认生产**；Remotion 用于预览对齐与精品成片。  
- 帧字段对齐现有 `ScriptVideo`，以便跟读剧场与片段渲染复用。

### 4.3 包体示意

```yaml
id: narrative-manyu-lantern-e01
title: The First Lantern
kind: narrative_story   # 待定枚举；挂剧本侧
level: L1
source:
  license: original
  attribution: ManYu
beats:
  - id: beat-01
    speaker: Narrator
    text: "The town was quiet before the festival."
    emotion: calm
    audio: assets/audio/beat-01.wav
    background: assets/img/street-dusk.jpg
  - id: beat-02
    speaker: Lilia
    text: "Come on — the lanterns are waiting."
    emotion: warm
    audio: assets/audio/beat-02.wav
    background: assets/img/street-dusk.jpg
    sprite: assets/img/lilia.png
    followRead: true          # 可进跟读剧场
video:
  full: assets/video/episode.mp4
  engine: ffmpeg
square:
  allowClipPublish: true      # 跟读片段可发广场
```

## 5. 和现有剧本能力的复用

| 已有能力 | 叙事包怎么用 |
|---|---|
| 剧本商店 / 安装 / 离线包 | 同 story/nqtr 安装链路，分类区分 |
| 跟读剧场 / frames 时间轴 | 直接喂 narrative beats |
| script-video / Remotion·ffmpeg | 官方成片生产 + 用户片段渲染 |
| 广场发布 | 片段作品；与轻量包「整段作品」并存，UI 用标签区分 |
| 会员锁剧本 Tab | 叙事包同样走剧本侧会员策略（与现网一致） |

## 6. MVP 范围（下版本）

### 做

- 1 个试点叙事包（优先漫语町原创短篇，成片 ≤ 8 分钟）。  
- 半自动生产：分镜表 → Hume / NovelAI → ffmpeg → 人工过片。  
- 剧本中心可安装、可观看、可进跟读剧场。  
- 跟读片段发布到广场（最小可用即可）。  

### 先不做

- 博客包、资讯广场、学习计划接入。  
- Ink 分支 / NQTR 化叙事包。  
- 全自动无人质检量产。  
- Remotion 作为默认量产引擎。  
- 底部 Tab 改名（有实际品类压力再说）。

## 7. 风险

| 风险 | 对策 |
|---|---|
| 和轻量剧情包看起来像同一个 | 商店分类 + 文案：「练习口语」vs「看故事」；封面与完成态不同 |
| 运营成本（出图出声） | 少包做深；角色卡复用；不做博客/新闻线 |
| 版权 / AI 商用 | 来源白名单；ToS 确认后再量产 |
| 只看不跟读 | 允许；跟读与发布是增强，不设题海门槛 |
| 广场作品类型变杂 | 用 `练习作品` / `叙事片段` 标签分流，不混资讯 |

## 8. 开放问题

1. 产品名：叙事短剧 / 剧情短片 / 别的？  
2. 技术枚举：`packageType` 新建（如 `narrative`）还是 `contentMode` 扩展？  
3. 试点用漫语町原创还是公有领域寓言？  
4. 片段发布：最短几句、是否必须含画面？  
5. Hume / NovelAI 商用与预算？  
6. 默认成片清晰度：540p15 vs 720p24？

---

## 9. 总评

**收口正确：** 叙事进剧本、练习留轻量包、砍掉博客/资讯，运营面可控，也更符合漫语町「剧情」重心。  

技术上继续站在跟读剧场 + ffmpeg/Remotion 短片管线上；产品上把「看故事」和「为练习而存在的口语剧本」在分类与文案上拆开，广场只多一种**跟读片段**，不加新闻流。先一个试点包验证观看 → 跟读 → 片段发布闭环即可。

# 漫语町产品功能现状与实施路线图

> 版本：v1.0
> 核对日期：2026-08-03
> 状态：依据当前前端、后端、Prisma Schema 与移动端代码核对后的实施基线

## 1. 结论摘要

此前提出的 9 个方向并非都从零开始。当前项目已经形成“学习包 → 今日任务 → 输出热身 → VN 对话 → AI 分析 → 学习本复练 → 离线同步”的主体闭环。

最需要避免的是重复建设：

- 沉浸式播放器、离线学习、间隔复习、学习提醒已经有可用实现，应进入验收、统一和增强阶段。
- AI 自由对话已经有后端生成接口、额度控制和后台预览，但缺用户端入口、会话持久化和完成闭环。
- 发音建议、学习报告已有基础数据或弱反馈；发音能力保持当前辅助定位，不作为近期独立产品方向。
- 写作练习、分级阅读尚未形成用户功能。

因此，下一阶段建议按以下顺序投入：

1. 产品化 AI 对话伙伴。
2. 收口现有播放器、SRS、离线和提醒能力。
3. 上线写作练习 MVP。
4. 建立可信的学习报告。
5. 扩展分级阅读，并让阅读任务回到口述或摘要写作输出。

## 2. 核对口径

状态定义：

| 状态 | 含义 |
| --- | --- |
| 已实现 | 用户端存在可访问入口，核心数据与交互闭环已工作 |
| 基本实现 | 主链路已工作，剩余工作以设备验收、统一口径或体验增强为主 |
| 部分实现 | 已有可复用接口、模型或后台工具，但缺用户端完整闭环 |
| 未实现 | 只有通用技术基础或设计想法，没有独立业务入口和数据闭环 |

本次核对以代码为准。以下旧资料只能作为历史参考：

- Copilot memory 中的 `frontend-features-overview.md` 仍记录 React 18、5 个 store；当前为 React 19、17 个 store。
- `backend-modules-overview.md` 记录 20 个模块；当前 `apps/backend/src/modules` 下已有 26 个模块，并增加学习包、同步、字典、AI 模型、剧情社区、后台任务等能力。
- `learning-packages-status.md` 描述的是旧 CSV 文件包生产状态；当前正式链路已经转为后台构建、发布 zip、客户端 SQLite 安装与资源缓存。

## 4. 逐项代码依据与范围

### 4.1 AI 对话伙伴

已有：

- `apps/backend/src/modules/practice-ai/english-practice-ai.controller.ts` 暴露 `POST /practice-ai/scene-roleplay-turn`。
- `english-practice-ai.service.ts` 支持角色身份、性格、场景提示、最近对话、学习目标、建议回复和简短中文反馈。
- `AiQuotaService` 已接入对话额度。
- `narrative-world-studio.tsx` 可以在后台预览 AI 自由对话。

边界：当前用户端路由没有自由对话页面；该接口也只被后台管理功能调用。因此它不是“已上线 AI 对话伙伴”，而是“核心生成能力已完成”。

### 4.2 写作练习

已有基础仅限通用 LLM、配额、反馈卡和文本输入能力。当前没有 writing 路由、写作题目模型、草稿记录或写作批改服务，不应标记为部分上线。

### 4.3 沉浸式播放器

已有：

- `features/learning/components/immersive-player/` 包含播放器、队列映射、设置持久化与播放服务。
- `ExpressionLibraryPage` 已提供用户入口。
- 缺音频时按需调用 TTS，原生端优先写入资产缓存。
- 原生端使用 `@capgo/capacitor-native-audio` 和 `@capgo/capacitor-media-session`，已实现后台播放参数、媒体元数据和锁屏控制动作。

边界：前台业务功能已覆盖原设计主体，Native Audio 与 Media Session 桥接也已接入；但当前工作区无法核验 iOS `UIBackgroundModes = audio`，且没有 Android 原生工程和媒体前台服务，不能宣称锁屏后台播放已完成。

### 4.4 间隔重复与闪卡

保留两类不同业务对象的进度实体：

- 学习本：`LearningNotebookItem` 保存 `reviewCount`、`intervalDays`、`easeFactor`、`lapseCount`、`nextReviewAt`。
- 今日任务：`UserWarmupItemProgress` 保存同构排期字段；客户端支持离线排期，服务端根据幂等 attempt 历史重放并返回权威进度。

它们不是同一张数据表的重复实现：前者安排用户收藏的单词、句块和句型，后者安排学习包里的 Warmup 练习题。2026-08-03 已统一到 `Again / Hard / Good / Easy` 评分和同一套 SM-2 规则；Warmup 映射为 `weak/miss → Again`、`ok → Good`、`strong → Easy`。前两次成功间隔为 1、6 天，之后基于上一次 `intervalDays × easeFactor` 递推；失败重置成功次数并增加 lapse。

学习本的手动状态接口现在只改变 `masteryStatus`，不会更新 `lastReviewedAt` 或触发排期；真实复习通过独立 `POST /expressions/notebook-items/:id/review` 提交评分。剩余缺口是用户端专用闪卡复习会话尚未接入该接口。

### 4.5 发音评估

目前能够录音、转写并让 LLM 给出发音建议，剧本跟读模式也已经存在。该能力已满足当前辅助定位；产品核心是主动表达、对话和写作，不追求标准口音训练，因此近期不接入专业发音评测。

产品文案继续使用“发音建议”，不宣传为“音素级评分”。未来只有在用户需求和产品方向发生变化时，才重新评估音频评测服务或 forced alignment。

### 4.6 分级阅读

当前没有独立分级阅读路由、内容模型和阅读记录。地图中的 reading 线索、教学 Markdown 或英文理解题都不等同于分级阅读产品。

### 4.7 学习报告与能力评估

已有：

- AI 入门测评会写入用户 `outputLevel` 与 `outputLevelDetail`。
- Profile 有总练习、学习本内容、Chunk 掌握、连续天数和练习记录。
- `activity-heatmap` 汇总日活跃、题数和有效时长。
- `week-tracker.tsx` 已有周/月/年展示。

缺口：

- 当前等级是产品内部 L1～L5，不是经过标准化校准的 CEFR A1～C1。
- 缺少“本周相比上周”的稳定聚合、技能维度证据和自动生成报告。
- 周/月/年趋势已经移除 mock fallback；没有学习数据时按真实的零值展示。

### 4.8 离线学习

正式链路已经包括学习包 zip、manifest/checksum、SQLite 内容表、Filesystem 资源缓存、暂停/恢复、卸载、资源引用和离线 outbox。它已经是产品基础设施，不应再列为全新功能。

### 4.9 学习提醒与习惯养成

已有本地通知设置、权限申请、未来 7 天滚动排程、完成今日任务后取消当天提醒、App 角标、连续打卡、成就与活动热力图。后续重点应是提醒效果和策略，不是重写提醒系统。

## 5. 推荐实施计划

### Phase 0：收口现有能力（1 个迭代）

目标：把“代码存在”提升为“可稳定交付”。

1. 沉浸式播放器完成 iOS/Android 真机测试矩阵：前后台切换、锁屏、耳机控制、来电打断、弱网、连续队列。
2. 学习本与 Warmup 已保留各自进度实体并统一调度内核；继续完成学习本闪卡复习会话和跨入口统计口径。
3. 学习趋势已移除 mock fallback；继续完善无数据时的空态文案和引导。
4. 为离线安装、今日任务、播放器、提醒补充关键埋点和错误码。
5. 修复当前前端全量 TypeScript 基线错误，恢复 CI 可用性。

验收：现有四项能力有真机验收记录、无演示数据冒充真实数据、关键失败可观测。

### Phase 1：AI 对话伙伴 MVP（2 个迭代）

目标：把已有生成接口变成用户可持续使用的训练产品。

范围：

1. 新增用户端 `/conversation` 入口与场景选择页。
2. 复用角色、地点、学习目标和 `scene-roleplay-turn`。
3. 增加会话与轮次持久化；支持刷新恢复、主动结束和历史查看。
4. 结束时生成目标命中、表达问题、推荐复练项，并写入学习本。
5. 接入 AI 额度、会员边界、超时重试、内容安全和敏感输入处理。
6. 首版只支持文本与语音转写输入，不把实时语音通话纳入 MVP。

验收：用户可选场景完成 5～10 轮对话，退出后可恢复，结束后能看到总结并进入复练。

### Phase 2：写作练习 MVP（1～2 个迭代）

目标：增加第二种主动输出通道。

范围：

1. 首版只做日记、场景消息/邮件、IELTS 段落三类模板。
2. 保存题目、草稿、提交版本、评分维度和 AI 反馈。
3. 反馈拆成任务完成度、结构、语法、词汇与改写建议。
4. 支持“根据反馈再写一次”，展示前后版本差异。
5. 把高价值改写句一键加入学习本。

不做：协作文档、长篇作文编辑器、实时逐字纠错。

### Phase 3：可信学习报告（1 个迭代）

目标：让用户看到真实进步，而不是只堆统计卡。

范围：

1. 后端新增按周聚合 DTO，统一时长、题数、通过率、目标表达使用和复练完成率。
2. 生成“本周变化、优势、需要巩固、下周建议”四段报告。
3. 能力图只展示有证据的数据维度；没有发音引擎前不伪造发音分。
4. 内部 L1～L5 与 CEFR 分开显示；完成校准前使用“参考范围”而非认证等级。
5. 支持分享卡片和本地提醒跳转。

### Phase 4：分级阅读（2 个以上迭代）

先建设内容模型和生产管线，再做阅读器：

1. 定义文章、段落、CEFR、主题、词数、目标词与理解题。
2. 后台支持导入、AI 辅助分级和人工校验。
3. 用户端支持点词、音频、阅读进度、理解题和生词入学习本。
4. 阅读完成后的输出任务优先采用口头复述或摘要写作，使其回到输出训练主线。

## 6. 暂不建议新增的重复系统

- 不再新建第二套离线数据库或下载器。
- 不再新建独立“收藏单词表”；统一进入学习本与复习排程。
- 不为 AI 对话另造角色/地图数据，复用剧情共享资产。
- 不把 LLM 根据转写生成的建议包装成音素级发音评分。
- 不新增与今日任务平行的打卡系统，复用现有活动、提醒、角标和成就。

## 7. 文档维护规则

1. 产品能力状态以本文为总入口，专项文档负责设计细节。
2. 专项功能上线时，必须更新文档顶部的“状态、核对日期、代码入口、剩余边界”。
3. Copilot memory 不作为当前实现依据；代码改动后优先更新仓库 `docs/`。
4. 文档中的“建议、未来、Phase”必须标明已实施、部分实施或未实施，避免把已完成能力再次排期。

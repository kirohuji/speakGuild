# SpeakGuild 学习包命名与管理字段规范

## 用户标题

统一使用以下格式：

- 系列卷册：`系列名 · 第 N 册｜这一册能学会什么`
- 难度分篇系列：`系列名 · 入门篇`、`系列名 · 基础篇`、`系列名 · 进阶篇`（如“常用英语500句”）
- 独立课程：`内容类型｜核心主题`

标题不重复等级、题量和“学习包”三个字。等级由标签展示，数量写在描述中。“常用英语500句”保留为系列名，以入门篇、基础篇、进阶篇标识学习顺序；500 是系列目标，不是每篇的句数。避免同时使用冒号、破折号、“专项”“强化训练”等多套风格。

示例：

- `常用英语500句 · 入门篇`
- `英语时态活用 · 第 2 册｜经历、过程与结果`
- `日常微写作｜一句到五句`
- `趣味阅读｜英国历史与文化`

## Markdown 管理信息

每个可发布包的 `00-课程总设计.md` 必须在标题后放置“管理信息”表，至少包含：管理状态、用户标题、一级类型及 `packageType`、二级主题、内容体验及 `contentMode`、所属系列、`seriesSlug`、系列顺序、卷册名称、`requiredOutputLevel`、`requiredUserLevel`、前置学习包和 `requiredPrevious`。

字段必须与后台含义一致：

| 管理名称 | 数据字段 | 说明 |
| --- | --- | --- |
| 一级类型 | `packageType` | 日常、考试、故事、课程、零基础 |
| 二级主题 | `Scene.categoryId` 对应分类 | 后台可编辑主题标签，不表示学习顺序 |
| 内容体验 | `contentMode` | 练习、写作、阅读、听力、小说或剧情 |
| 所属系列 | `PackageGroup` | 用于归组展示；既可表示进阶课程，也可表示无强制顺序的兴趣集合 |
| 系列顺序 | `Scene.sortOrder` / `PackageGroupItem.sortOrder` | 只是组内展示顺序。Markdown 从 1 开始，落库时转换为从 0 开始 |
| 卷册名称 | `PackageGroupItem.volumeLabel` | 如“第 1 册”“基础篇” |
| 等级 | `requiredOutputLevel` | 进入该包所需最低输出等级，不代表所有话题只能有同一难度 |
| 前置学习包 | `ScenePrerequisite` / `requiredPrevious` | 与系列顺序分开管理；只有确有依赖时设置，不强迫兴趣包或同级能力包依次完成 |

`管理状态` 是内容制作流程标签：`planned` 和 `template` 落库前对应草稿，不直接写入 Prisma 枚举；`active` 对应发布，`deprecated` 对应归档。实际数据库分别使用 `LearningPackageStatus` 和 `PackageGroupStatus` 的现有取值。

## 生命周期

- `planned`：框架已确认，尚未生成完整数据。
- `building`：正在制作或迁移 CSV、题目和媒体。
- `active`：通过审校，可以发布。
- `deprecated`：旧包或重复包，仅用于迁移与追溯。
- `template`：剧情或小说的制作模板，本身不是用户可见学习包。

废弃包必须写明 `替代学习包` 和 `废弃原因`。不直接删除带真实数据的旧目录，待材料、用户进度和引用迁移完成后再归档数据库记录。

## 防止过度拆分

- `requiredOutputLevel` 是最低进入等级，不要求包内所有话题难度完全相同。
- 4–5 个抽象主题且不足 12 个实质任务的分包应合并。
- 独立包原则上应支持至少 3 周学习；语言材料包不少于约 50 个主动目标，读写听包不少于 10–12 个实质任务。
- 只有内容量大、前后能力有明显跃迁、并且每卷都能独立产生完成感时才拆卷。
- 同一系列标题必须保持相同系列名和卷册格式；选择编号时统一编号，选择难度分篇时统一使用“入门篇／基础篇／进阶篇”，不在同一系列内混用。
